# 决策卡片 #118
- **日期**：2026-08-28 | **阶段**：MVP

## 决策问题
实名「手动通过」混在用户列表里，运营要同时看套餐/押金和审证件。要不要拆开？

## 调用的大师视角
- 俞军：审认证是独立任务（核三要素），和查用户档案不是同一体验；拆开降低替换成本。
- 乔布斯：列表只留档案；待审单独成队列。不新开菜单、不加第四种实名状态。

## 核心判断
**用户档案与待审认证分成两个页内 Tab；待审数量标在 Tab 上。不新开侧栏菜单。**

| 项 | 规则 |
|----|------|
| 用户列表 / 用户信息 | 套餐、服务、押金；实名仅 **已实名 / 未实名**；操作仅 **查看实名信息**（已实名） |
| 待审认证 | 仅 **未通过**（机审驳回、须人工核对）；不在用户列表展示该状态 |
| 角标 | 页内 Tab 文案 `待审认证 (N)`，N=当前范围未通过人数；0 不显示数字 |
| 待审列 | 用户、姓名、证件号（脱敏）、提交时间、驳回原因、操作（查看 / 手动通过） |
| 通过后 | 变已实名，离开本队列；留痕不变（decision-097） |
| 范围 | 运营商=本主体；平台=全平台。**入口**：运营商「用户」页内 Tab；平台「用户信息」页内 Tab（不占侧栏二级） |

## 反方最强论据
运营习惯在用户行上直接点「手动通过」。缓解：未通过只进待审 Tab；列表把未通过显示为未实名，档案（套餐/押金）仍可查。

## 失效条件
监管要求所有提交（含机审中）都必须人审，或取消人工通过。

## Non-goals
- 不新增「待审核」第四态（仍三态）
- 待审 Tab 不做通过/驳回以外的用户档案编辑
- 不改骑手端提交流

## 下一步验证
- 运营商「用户」侧栏仍是一项；页内 Tab 在筛选项上方：用户列表 / 待审认证 (2)
- 用户列表实名仅已实名/未实名；操作仅查看实名信息；U1055/U2301 在列表显示未实名，在待审 Tab 为未通过
- 待审 Tab 仅 U1055、U2301；通过后角标减 1
- 平台「用户信息」页内同样有待审 Tab；侧栏二级仍是用户信息 / 押金统计 / 服务变更

## 知识沉淀
待办队列和主数据列表要分开；角标只数「现在必须处理」的单。
