# 决策卡片 #152
- **日期**：2026-11-23 | **阶段**：发布

## 决策问题
服务冻结规则是否由平台统一定死，还是允许运营商覆盖？

## 调用的大师视角
- 俞军：运营商差异化冻结（淡季休班）净价值 − 平台默认一致性成本 − 客诉解释成本；可配天数/次数后净价值 > 0。
- 乔布斯：配置项压到三件事——允不允许冻、冻多久、冻几次；其余派生。
- 贝佐斯：逆向工作法——骑手只感知「能不能冻 / 还剩几天 / 是否自动解冻」，后台两层配置对 C 端透明。

## 核心判断
**平台维护全局默认冻结规则；运营商可整包覆盖。** 仅个人套餐；人天池不适用。

| 项 | 口径 |
|----|------|
| 平台默认（现行升格） | 单次最长 **10** 天；**不**关闭天数限制；每套餐周期 **1** 次；到期**自动解冻**并恢复计费（有效期按已冻天数顺延） |
| 运营商覆盖 | 可改下列三项；未覆盖则用平台默认 |
| 单次最长天数 | 整数 ≥ 0；**`0` = 不允许冻结**；`≥1` = 最长 N 天（未关闭限制时） |
| 关闭单次天数限制 | 布尔；开 = **不限单次时长**、**不**自动解冻（须手动解冻）；与「天数=0」互斥（天数=0 时不可开） |
| 每周期可冻结次数 | 整数 ≥ 0；**`0` = 不限次数**；`≥1` = 本套餐服务周期内最多 N 次 |
| 自动解冻 | 派生：未关闭天数限制且天数≥1 → 到期自动解冻；否则不自动解冻 |
| 申请条件（不变） | 个人套餐、服务中且有效期内、**未持电**；满足即系统生效 |
| 解冻（不变） | 用户可自行解冻；解冻后 `valid_to` 顺延；首服为领电 |
| 快照 | 以**申请冻结时**解析结果计时/计次；改配置不回溯进行中的冻结单 |
| 解析 | `运营商覆盖 ?? 平台默认` |
| 入口 | 平台：统一定价/规则区「服务冻结」；运营商：平台设置 →「服务冻结」 |

## 反方最强论据
运营商把天数设 0 或次数极严 → 骑手找不到冻结入口，客诉落到平台。缓解：C 端展示不可冻原因；平台默认保持可冻。

## Non-goals
- 人天池 / 设备租赁白名单冻结
- 区县/站点级冻结规则
- 冻结期间分段计费或占用费
- 运营商审核冻结/解冻（仍自动生效）

## 下一步验证
- 平台默认 10 天 / 1 次；OP-SX 覆盖为天数 0 → C 端不可申请冻结
- OP-SX 关闭天数限制 + 次数 0 → 可多次冻、不自动解冻
- AC / 原型设置页 / `userCanApplyFreeze` 闸门对齐

## 知识沉淀
「0」在天数与次数上语义相反：天数 0=关能力，次数 0=不限额；关闭天数限制是第三态，不要塞进同一个数字。
