# 决策卡片 #110
- **日期**：2026-08-21 | **阶段**：MVP

## 决策问题
推广链接是否保留「链接码」与系统 ID 两套唯一标识？

## 调用的大师视角
- 乔布斯：两套唯一键是假选择；运营只要一个能对单的 ID。
- 诺曼：URL 参数应与列表展示同一字符串，避免「码」和「ID」对不上。

## 核心判断
**去掉链接码，唯一标识为链接 ID。**

- 列表、购卡记录、平台营销链接展示 `ID`（如 `LNK-C001`）。
- 小程序 `lnk=` 使用同一 ID。
- 订单写 `channel_id` + 首触 `link_id`。
- 专享价、24h 归因、佣金规则不变。

## 反方最强论据
可读 slug（`qsk-30d-home`）更适合投放后台口述。失效条件：投放侧强制要求短码且不愿使用 `LNK-` 前缀。一期以对账清晰优先。

## Non-goals
- 不改 24h 归因、首笔专享价、佣金分账
- 不做旧 `lnk` slug 兼容（原型无已发出链接包袱）

## 下一步验证
- 套餐与链接：无「链接码」列，有 ID；小程序链接含 `lnk=LNK-…`
- 购卡记录：ID 列与链接列表一致
- 新建链接：生成 LNK- 开头 ID，URL 带该 ID

## 知识沉淀
链接实例一个主键即可；用途是备注，ID 进 URL。见 decision-093。
