# 决策卡片 #124
- **日期**：2026-09-04 | **阶段**：MVP

## 决策问题
「退款设置」（套餐/押金自动·手动、冷静期说明）应放在「订单与服务 → 退款管理」内，还是运营商「平台设置」下？

## 调用的大师视角
- 唐·诺曼：配置与作业心智模型不同；设置应与押金数额等同属「规则配置」，审核队列属「日清作业」。
- 乔布斯：退款管理只做待办与处理；设置不塞进作业页三级 Tab，减少误触与认知噪音。

## 核心判断
**退款设置迁至运营商「平台设置」二级 Tab，与押金设置并列；退款管理仅保留申请队列。配置仍按运营商主体独立（非平台统价）。**

| 项 | 规则 |
|----|------|
| 入口 | 平台设置 → **退款设置**（在押金设置后） |
| 作业 | 订单与服务 → 退款管理 = 仅申请/审核 |
| 快捷 | 退款管理 KPI「套餐/押金模式」跳转至平台设置·退款设置 |
| 权限 | 切换模式仍需 `refunds.audit`；有 `refunds.view` 可进平台设置看本页 |
| 冷静期 | 仍只读说明，始终须审 |

## 反方最强论据
财务天天审退款，设置放作业页更近。拒绝：改模式低频；与押金规则同放设置更一致，避免作业页膨胀。

## 失效条件
平台强制全网统一退款模式（运营商不可配）→ 改到平台端统价/策略，运营商只读。

## Non-goals
- 不改自动/手动业务规则与冷静期强制人工
- 不把设置做成平台角色「平台统价」页

## 下一步验证
- 运营商 → 平台设置 → 退款设置：可切换套餐/押金模式
- 退款管理页无「退款设置」Tab；KPI 可跳转
- 王会计（refunds）可见平台设置并改模式

## 知识沉淀
规则配置进「平台设置」，日清队列进「订单与服务」；同主体配置、不同导航意图。
