# 决策卡片 #122
- **日期**：2026-09-01 | **阶段**：MVP

## 决策问题
链接类渠道和运营商线上结算时，要不要单独搞一套进件子商户？还是直接复用运营商那张对公卡？

## 调用的大师视角
- 乔布斯：打款只需要一张对公卡；渠道侧再维护微信/支付宝进件表是噪音（与 decision-106 同一刀）。
- 俞军：新体验 = 填四项就能收线上佣金；旧体验 = 先开子商户再绑对公；替换成本低。

## 核心判断
**链接类线上结算的收款账户 = 与运营商相同的唯一对公银行卡。平台管理方式也相同。**

| 项 | 规则 |
|----|------|
| 谁要填 | 结算模式=链接类，且与运营商为**线上结算**（佣金及时到付） |
| 字段 | 开户名称、银行卡号、开户银行、开户支行；联行号选填 |
| 数量 | 同一时间仅 1 户；变更覆盖，不解绑删除 |
| 渠道 | 侧栏「收款账户」自行添加/变更 |
| 平台 | 渠道商管理 → 详情：查看、代添加、代改（同运营商详情） |
| 拦截 | 未绑定不可开启线上结算 |
| 线下 | 同一张卡供运营商打佣；未绑可暂空，开启线上前必须绑 |

## 反方最强论据
即时分账走微信/支付宝，没有子商户页财务会以为通道没开。拒绝：C 端款仍进运营商子商户；渠道要的是佣金打到哪张对公卡，与支付进件解耦。

## 失效条件
监管要求佣金必须进渠道支付子商户且四要素核验 → 再加进件，而不是取消对公卡。

## Non-goals
- 不改人天池（无收款账户）、设备租赁/资方的进件表
- 不做小额鉴权、平台审卡
- 平台仍不新增/编辑渠道主体

## 下一步验证
- 平台 → 运营商管理 → 渠道商管理：骑士卡（线上）详情见已绑对公卡，可代改
- 闪送骑士卡（线下）详情为空态，可代添加；添加后字段与运营商一致
- CH-CARD 登录「收款账户」：唯一卡详情，不是进件表格
- 运营商签约开启即时到付：CH-DELIV 未绑卡被拦截

## 知识沉淀
谁收 C 端款（运营商子商户）和佣金打到哪（渠道对公卡）要拆开。链接类账户复用运营商模型，不要为渠道再造一套。
