# 决策卡片 #140
- **日期**：2026-09-14 | **阶段**：发布 / 双边补齐

## 决策问题
运营商缺少与渠道商「推广链接类」结算的模块，要不要做、放哪、叫什么？

## 调用的大师视角
- 王慧文（双边）：渠道已有「佣金对账」，运营商是付款/确认方却没有对页，账在一边合不拢。
- 乔布斯（减法）：不把佣金台账塞进「渠道订单」（人天 PO / 月租 MO / 激活码 AC 是 B2B 采购单）；也不和「渠道权益 → 渠道分销」SKU 概况混成一页。

## 核心判断
**新增运营商「渠道管理 → 链接结算」独立 Tab**（签约渠道、渠道订单之后，渠道权益之前）。

| 项 | 口径 |
|----|------|
| 命名 | **链接结算**（付款方）；渠道侧仍叫 **佣金对账** |
| 粒度 | 自然月 × 渠道 × 结算方式拆行（decision-065） |
| 即时分账 | 支付时已完成，本页只读，状态=已即时分账 |
| 线下 | 待线下结清 / 已线下结清；运营商登记流水号+日期（记账，不走支付通道） |
| 渠道对账 | 线下状态仍为 ——（decision-074），渠道不点「已结清」 |
| 退款冲正 | 渠道不向骑手退款；`round(原佣金 × 退套餐费 ÷ 原套餐实付, 2)`（decision-137） |
| 空态 | 无链接类签约 → 引导去签约渠道 |
| 权限 | [假设] 复用 `channel_sales.view`，不拆「登记结清」独立权 |

## 反方最强论据
「渠道订单」加第四 Tab 更省菜单。反对：订单是 B2B 到账确认，佣金是 C 端购卡后的应付；混用会导致确认到账与结佣两套状态互相污染。

## Non-goals
- 不改渠道「佣金对账」线下 —— 口径
- 不在本页做真实打款 / 招行分账
- 不提供撤销已登记结清
- 不新增平台侧链接结算监管页
- 不把渠道权益·渠道分销改成台账
