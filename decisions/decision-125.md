# 决策卡片 #125
- **日期**：2026-09-04 | **阶段**：MVP

## 决策问题
1）按次套餐（次卡 / 单次）是否允许生效后退款？2）退款设置里自动/手动切换要不要二次确认？

## 调用的大师视角
- 第一性原理：按次是「次数商品」；生效后履约能力已交付，剩余次数公式退款等于事后议价，纠纷与套利成本高。
- 唐·诺曼：自动↔手动是高影响配置，单击即切违反防呆；须明示后果再确认。

## 核心判断
**按次套餐一旦生效，不允许退套餐费（含冷静期、中途完结、SKU 退订）。未生效（首次领电且未领电）可全额退。切换套餐/押金退款模式须确认弹窗。**

| 项 | 规则 |
|----|------|
| 范围 | `times` / `single`（次卡、单次换电）；**不含**按天 1 天畅换 |
| 生效 | 服务已开通（立即生效=支付成功；首次领电=领电成功） |
| 未生效 | 待激活未领电 → 可全额退套餐费（待激活退订） |
| 生效后 | C 端无退款入口；后台不接受套餐费退款申请 |
| 押金 | 仍按押金退还规则，与本条独立 |
| 模式切换 | 点选另一模式 → 弹窗说明影响 → 确认后生效；点当前模式无操作 |

## 反方最强论据
次卡剩多次不退伤体验。拒绝：按次定价已含次数风险；要退只能未生效取消，避免按次摊算扯皮。

## 失效条件
监管强制要求按次剩余可退 → 恢复剩余次数公式并单独公示。

## Non-goals
- 不改按天套餐（包月/7天/1天）冷静期与中途退规则
- 不做模式切换的审批流或双人复核

## 下一步验证
- 平台设置 → 退款设置：规则表「次卡 / 单次」为生效后不可退；1 天单独一行
- 切换自动/手动：有确认弹窗；取消不改
- 点已选中模式：无弹窗

## 知识沉淀
按次=生效即不可退套餐费；配置开关=二次确认防误触。
