# 决策卡片 #096 · 套餐主型号 + 可换兼容集

| 项 | 内容 |
|----|------|
| 日期 | 2026-07-31 · 锁定补丁 2026-08-03 |
| 阶段 | MVP / 发布前规则修正 |
| 结论 | **已锁定**：定价绑主型号 A；换电按可换集 S；**兼容双向**；**兼容关系挂平台电池型号字典**（非 SKU）。085「无一单通兑」= 不可兑未进兼容关系的型号 |

## 决策问题

用户套餐对应主型号 A，但业务上 B、C 也能用——如何设计隔离。

## 已拍板（2026-08-03）

| # | 议题 | 结论 |
|---|------|------|
| 1 | 兼容方向 | **双向**：A 兼容 B ⇒ B 套餐也可换 A（关系无向） |
| 2 | 配置落点 | **平台电池型号字典**维护兼容；套餐/白名单只选主型号，换电时查字典算 S |

## 调用的大师视角

- **俞军**：字典统一兼容，避免每条 SKU 配一套导致错配成本。
- **乔布斯**：C 端无感；后台只维护型号关系。
- **第一性原理**：隔离边界 = 型号字典导出的无向兼容闭包（见下）内。

## 核心判断

### 1. 售卖 vs 换电

| 字段 | 来源 | 用途 |
|------|------|------|
| 主型号 A | 套餐/白名单 SKU（085 唯一键） | 定价、展示、优先出电 |
| 可换集 S | **型号字典**计算，不写在 SKU 上 | 开仓取电 / 持有校验 |

### 2. 型号字典 · 双向兼容（落地规则）

- 字段：型号上的 `compatible_model_ids[]`（不含自身）。
- **无向同步**：在 A 上勾选/取消 B，保存时自动在 B 上写入/删除 A。
- **多选互兼容**：在 A 上一次勾选 B、C 并保存时，写入 **完全图**（A↔B、A↔C、B↔C），避免「都能跟 A 换、B 与 C 却不通」的认知坑。
- 计算：`S(A) = {A} ∪ compatible_model_ids(A)`（直接邻居 + 自身；完全图下 A/B/C 的 S 相同）。

### 3. 换电匹配

```text
扫柜
  → 主型号 A ← 有效套餐/白名单
  → S ← 型号字典.S(A)
  → 持有电池：持有 ∈ S（否则仅还电/阻断取电）
  → 满电：model ∈ S（优先 A，再其他）
  → 空仓：可接收当前持有型号
  → 先还后取
  → S 内无满电 → 本柜暂无你可换的型号
```

### 4. 与历史决策

| 原结论 | 现状 |
|--------|------|
| 085 无一单通兑 | **保留语义**：未进字典兼容关系的型号不可兑 |
| 095 满电必须 =A | **废止**；改为 ∈ S（096） |
| 096 待确认方向/落点 | **已关闭**（双向 + 型号字典） |

### 5. 出电优先级

1. 优先主型号 A 满电  
2. 再 S 内其他型号  
3. 用户不手选仓口  

## 反方最强论据

双向 + 完全图会使低价主型号更容易吃到高价库存。  
**应对**：字典兼容由平台谨慎配置；监控主型号命中率；不兼容的型号不要互挂。

## Non-goals

- SKU 级覆盖可换集（一期不做）  
- 用户手选型号/仓口  
- 未配置时默认全型号互通  
- 取消套餐主型号（定价仍绑 A）

## 支持 / 反对 / 失效

| | 内容 |
|--|------|
| ✅ 支持 | 业务确认双向；字典一处维护、全网一致 |
| ❌ 反对 | 误配一张完全图等于变相通兑 → 靠权限与变更审计 |
| ⚠️ 失效 | 型号无法识别；或财务强制禁止任何跨型号 |
