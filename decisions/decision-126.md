# 决策卡片 #126
- **日期**：2026-09-07 | **阶段**：MVP

## 决策问题
人人已做额度分配时，是否仍保留「每日 0 点整批预占 → 确认/释放」作为人天扣减主路径？

## 调用的大师视角
- 乔布斯：分配已锁个人库存后，再晨间整批预占是第二套账，认知噪音大于收益。
- 俞军：新体验（个人剩余闸门 + 用则扣）相对旧体验（预占）替换成本低、对账更短，净值 > 0。

## 核心判断
**主路径取消整批预占。闸门看个人剩余人天；当日有换电或日终仍持电则确认消耗 1；未用则不扣。预占不再作为对外主概念。**

| 项 | 规则 |
|----|------|
| 闸门 | 在职且 `remainingDays ≥ 1` → 可换电；否则不可换（持电仅可还） |
| 确认消耗 | ① 当日首次成功换电；或 ② 日终仍持电池且当日尚未确认 → 各扣 1 人天（每日最多 1） |
| 未使用 | 无换电且未持电 → **不扣**，无需「预占→释放」 |
| 池账 | 分配时从池可用划到个人；确认消耗时个人剩余 −1、池已消耗 +1 |
| 待还电 | 剩余=0 仍持电；原因统一优先 **个人无额度**（废止主路径「预占失败」） |
| 未分配骑手 | 剩余=0，不可换电；不引入共享池晨间抢占 |
| 余额不足预警 | 仍用 decision-113：可用 &lt; 在职×10（管续费跑道，不绑预占） |

## 反方最强论据
没有晨间整批锁，会超卖。拒绝：天数已在分配时划出；超卖面在「分配是否超额」，不在换电瞬间。

## 失效条件
恢复「不分配、全员从池可用实时抢扣」→ 才需要共享池预占/锁库存。

## Non-goals
- 不改为按次换电扣人天（仍自然日最多 1）
- 不取消持电也确认消耗
- 不改批发已结清、消耗不再向运营商二次收款

## 下一步验证
- 天数池文档/说明：主路径无「0 点预占」
- 骑手状态：今日可用 / 已消耗 / 个人无额度·待还电
- AC：预占确认 → 按日确认消耗；零额度原因不再强调预占失败

## 知识沉淀
有个人分配后：人天=个人余额日记账；预占是共享池时代的遗留，主路径删除。
