# 决策卡片 #149
- **日期**：2026-11-10 | **阶段**：发布（二期原型）

## 决策问题
平台「管理员」页的角色模板是否从账号表单内嵌，升级为可单独维护的模块？

## 调用的大师视角
- 乔布斯：模板是权限包，维护入口应独立；管理员页只负责「选用」。
- 俞军：运营改一批账号权限时，改模板一次同步 > 逐人改勾选；替换成本明显下降。

## 核心判断
**在「管理员」下新增页内 Tab「角色模板」，支持独立 CRUD（超管模板受保护）。**

| 项 | 口径 |
|----|------|
| 入口 | 平台 → 管理员 → **角色模板**（与「管理员列表」并列） |
| 系统预置 | 超级管理员 / 运营管理员 / 财务管理员；超管不可改、不可删、不可停用 |
| 自建 | 可新增 / 编辑名称·权限·启停 / 无人绑定时可删 |
| 与账号关系 | 表单下拉取启用中模板；改勾选与模板不一致 → 记「自定义」 |
| 同步 | 保存模板时，同步仍绑定该模板且未受保护的账号菜单权限与岗位名 |
| 范围 | 仅平台管理员；运营商/渠道员工权限模型不变 |

## 反方最强论据
多一层 Tab 增加理解成本。缓解：列表 KPI「角色模板」文案指向 Tab；表单内提示可去维护。

## Non-goals
- 不做按运营商/部门的模板隔离
- 不做模板版本历史
- 不把「自定义」做成可入库模板名（仍为账号级覆盖）

## 下一步验证
平台主体登录 → 管理员 → 角色模板：可见预置+客服样例；编辑运营模板后运营管理员权限摘要同步；删有绑定模板被拦截。

## 知识沉淀
权限包与账号解耦：模板库维护一次，人员只选包；自定义是逃生口不是主路径。
