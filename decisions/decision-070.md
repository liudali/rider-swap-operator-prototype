# 决策卡片 070 · 服务中不展示解冻块 · 中途完结套餐费与押金解耦

| 项 | 内容 |
|----|------|
| 日期 | 2026-07-24 |
| 阶段 | 发布前 |
| 结论 | **已锁定**：(1)「服务中」套餐详情不展示解冻/首服信息；(2)「中途完结」只退套餐费，押金不捆绑；退押前提为电池已还且订单完结，由用户自行申请 |

## 决策问题

1. 服务中详情出现「解冻后首服」干扰正常服务态扫读。  
2. 中途完结把套餐费与押金合成一笔，迫使用户同时处理押金，与「退押可选、须完结后申请」冲突。

## 调用的大师视角

- **乔布斯**：服务中砍掉解冻残留区块；中途完结砍掉「押金捆绑退」。  
- **俞军**：解耦后替换成本更清晰——先结清套餐费，押金另径决策。

## 已确认规则

| 项 | 规则 |
|----|------|
| 服务中详情 | **不展示**「解冻后首服 / 解冻信息」 |
| 中途完结 · 套餐费 | 单独展示可退套餐费 / 已退待退；进退款管理 |
| 中途完结 · 押金 | **不随单退**；说明块告知用户后续可自行申请 |
| 退押前提 | **电池已还回** 且 **订单/服务已完结** |
| 退押入口 | 「退款管理 · 押金退还」；用户决定是否申请 |
| 押金状态 | 中途完结期间实付押金仍为**在押**（非自动「退押中」） |

## 支持 / 反对 / 失效

- **支持**：减少误退押；服务态详情更干净。  
- **反对**：中途完结后用户可能忘退押，需骑手端/消息提醒 [待确认]。  
- **失效**：产品恢复「中途完结一键退套餐+押金」。
