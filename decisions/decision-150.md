# 决策卡片 #150
- **日期**：2026-11-13 | **阶段**：发布

## 决策问题
运营商客服电话是否按城市差异化配置？如何与默认号共存？

## 调用的大师视角
- 乔布斯：一个默认号 + 城市覆盖表，不搞「每个城市必填」。
- 俞军：多城运营商本地坐席价值 − 全国统一号体验差 − 覆盖配置成本；净价值 > 0。

## 核心判断
**平台设置新增「客服电话」：默认号必填；城市覆盖可选。** 骑手端按当前服务城市解析，有生效覆盖用城市号，否则默认号。

| 项 | 口径 |
|----|------|
| 入口 | 运营商 → 平台设置 → **客服电话** |
| 默认号 | 本运营商唯一；未覆盖城市一律用它 |
| 城市覆盖 | 城市唯一；电话 + 生效/停用 + 备注；停用/删除回退默认 |
| C 端解析 | 当前服务城市 → 生效覆盖 ?? 默认号 |
| 权限 | 同定价编辑（`pricing.edit` / 主体登录） |

## 反方最强论据
城市边界与「服务城市」定义不一致会导致打错号。缓解：文档写清按服务城市；原型示例用站点/套餐城市集合。

## Non-goals
- 不做区县/站点级电话
- 不做多号轮询、工作时间表
- 本迭代不改骑手端 UI 样式，仅定解析规则供 C 端接

## 知识沉淀
