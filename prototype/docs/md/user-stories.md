## 业务设定

### 一句话

每个角色用日常语言描述「我要完成什么业务结果」；细节字段与验收表见附录及验收标准全文。

### 怎么读

1. 先按角色扫本层故事，确认价值与边界。  
2. 要测原型或写用例时，用文末「故事 ↔ 验收」表跳到 [acceptance-criteria.md](./acceptance-criteria.md)。  
3. 骑手端主线步骤细节见 [骑手端PRD.md](./骑手端PRD.md)。

### 1. 平台管理员

- 作为平台管理员，我希望在**总览**看全平台大盘（运营商、渠道、用户、站点、设备、订单、流水、平台营收），以便掌握经营全貌。  
- 作为平台管理员，我希望在总览看各运营商保证金、信用额度与跨网状态，以便识别清分风险。  
- 作为平台管理员，我希望在**用户管理 → 用户信息**看到电池押金方式与押金状态分列、以及统一的持有电池信息，以便客服与风控溯源。  
- 作为平台管理员，我希望在**订单管理**查全平台套餐单、换电单与渠道批发单，并看到换电时「用户 / 柜机 / 电池」分属哪家运营商及跨网设备服务费，以便纠纷核查。（渠道批发单只读，不确认到账）  
- 作为平台管理员，我希望在**设备管理**用弹窗批量导入设备（先选运营商，再填或上传设备编号；类型与参数由物联网回填），以便设备直接归属运营商并可分配站点。  
- 作为平台管理员，我希望**不能**在平台侧新增/编辑渠道商主体，仅只读监管渠道额度与人天，以便权责清晰（渠道由运营商创建）。  
- 作为平台管理员，我希望在**流水管理**看用户支付、运营商间跨网日清与平台抽成明细，以便对账审计。  
- 作为平台管理员，我希望在**平台账户**看平台商户与本月 C 端分账、B 端计提构成，以便财务汇总。  
- 作为平台管理员，我希望在**运营商管理**维护运营商主体、查看并在必要时**代改收款账户**，以便入网治理与客服协助。（**已实现**）  
- 作为平台管理员，我希望在**保证金管理**核对运营商对公充值并确认入账或驳回，以便恢复保证金优先扣款路径。（**已实现**）  
- 作为平台管理员，我希望在保证金管理查看全平台保证金账本并手工调额/调信用（演示），以便异常补录。（**已实现**）  
- 作为平台管理员，我希望在**跨网统一定价**发布柜机/电池服务费与人天标准日值，以便全网规则统一、运营商只读遵循。  
- 作为平台管理员，我希望审核资方提交的租赁协议（校验承租方、设备编号与台账一致），通过或退回，以便租赁设备绑定前条款合规。（**拍板待落地**）

### 2. 运营商

- 作为运营商，我希望只管理**经平台绑定**的换电柜与电池（含租赁设备），以便权责清晰。  
- 作为运营商，我希望只看到**本主体设备产生**的套餐/换电订单与流水，以便对账准确。  
- 作为运营商，我希望管理自有站点及**换电范围**（是否允许跨网），以便控制用户换电地理边界。  
- 作为运营商，我希望维护**城市底价**（及二期价格分区），站点挂分区后可按套餐覆盖价格，未配则继承底价，以便偏远站补贴或差异化定价。  
- 作为运营商，我希望在**渠道销售**新增/编辑签约渠道、维护「一运营商一池」的卖方额度池，以便 B 端人天销售。  
- 作为运营商，我希望对线下「待确认到账」批发单确认到账后额度入池，以便采购款与额度对齐。  
- 作为运营商，我希望在**平台服务 → 运营商往来**同页切换概况、服务费明细、日清、周月，并在页内看到说明与筛选，以便连续对账。  
- 作为运营商，我希望在**平台服务费**分别查看 C 端支付分账与 B 端确认消耗/激活码计提，并按类型+时间筛选，以便区分两类成本。  
- 作为运营商，我希望在**保证金账户**查看清分专户、提交对公充值并跟踪确认状态，以便补足跨网清分保证金。（**已实现**）  
- 作为运营商，我希望在**员工**中维护运营员工权限，以便分工协作。  
- 作为运营商，我希望在月租金/融资相关账单查看各期应还；通过扫码或对公工单整单缴纳（**不做自动代扣**），以便履行还款义务。  
- 作为运营商，我希望在**站点管理**为各站配置场地合伙人及分润比例（一站可多位、同人多站可不同比例），以便场地方分享经营收入。（**已实现**）  
- 作为运营商，我希望在**站点合伙人**维护个人/公司档案，并查看分润绑定与明细，以便对账。（**已实现**）  
- 作为运营商，我希望合伙人建档时锁定个人/公司类型，开户完成后才能绑站/提现，以便收款主体合规。（**已实现**）  
- 作为运营商，我希望合伙人添加、调比例、解绑立即生效并留痕，历史分润不回溯，以便配置可审计。（**已实现**）  
- 作为运营商，我希望在站点管理维护场费电费，并在总览按月/站点查看场费分摊与当月电费，以便掌握站点成本。（**已实现**）  
- 作为运营商，我希望在「收款账户」自行绑定一张对公银行卡（开户名称、卡号、开户银行、开户支行），未绑定不可提现，以便平台审核后打款目标明确。（**已实现**）

### 3. 渠道商

- 作为渠道商，我希望向**签约运营商**采购人天（一运营商一池），增购不另开第二池，以便额度账本连续。  
- 作为渠道商，我希望创建骑手团队、登记骑手并分配/收回人天，离职强制回池，以便按骑手控额度。  
- ~~作为渠道商，我希望为团队配置周期上限~~（**已取消**）  
- 作为渠道商，我希望查看消耗明细、预占/确认状态，并在余额不足时看到可点的顶栏预警，以便及时续购。  
- 作为激活码渠道商（二期），我希望申请批发单，运营商确认到账后自动造码；可标记发放、申请作废，以便码生命周期完整。  
- 作为渠道商，我希望只读查看运营商个人套餐零售价；**渠道骑手零额度不可自费换电**。  
- 作为人天池渠道商，我希望**没有**面向 C 端的收款账户菜单，向运营商付款走 B2B 采购，以便与商业模式一致。（骑士卡等分销模式另有收款账户规则，见验收标准。）

### 4. 资金方

- 作为资金方，我希望在设备清单独立维护设备组合（新建/表格导入），并在清单内替换故障设备，以便与租赁协议解耦。  
- 作为资金方，我希望创建租赁协议时关联设备清单而非逐台勾选，且同一运营商可签多份协议对应多份清单。  
- 作为资金方，我希望协议由**运营商确认**生效，平台仅展示不参与审核，以便电子约定与线下合同对齐。（**2026-07-13 确认**）  
- 作为资金方，我希望在租金/还款收缴按账期跟踪扫码支付与对公工单，并审核运营商对公工单，以便到账后核销（**不做自动代扣**）。  
- 作为资金方，我希望调价、续期、改截止日、提前解约时与运营商重新确认（平台只读），以便承租方知情同意。（**2026-07-13 确认**）

### 5. 运营员工

- 作为运营员工，我希望用独立账号登录，**只看到被授权的菜单**，以便最小权限协作。  
- 作为运营员工，我希望数据范围限定所属经营主体，不能看其他主体数据，以便数据隔离。  
- 作为财务类运营员工，我希望在授权下查看流水、往来账、平台服务费与保证金账户，以便协助对公充值与对账。（**已实现**）

### 6. 团队管理员（渠道员工）

- 作为团队管理员，我希望用独立账号登录渠道后台，**仅看到本团队消耗明细**，以便管理本站点/本车队骑手换电情况。  
- 作为团队管理员，我希望导出本团队消耗明细，以便与渠道运营对账。  
- 作为团队管理员，我希望**不能**登记骑手、分配额度或改全渠道池规则，以免越权。

### 7. 骑手（微信小程序）

- 作为骑手，我希望在首页看附近换电站并一键扫码换电，以便快速取电。  
- 作为个人套餐用户，我希望在服务购买选择通用套餐并完成支付，以便开通换电权益。  
- 作为个人套餐用户，我希望服务中查看剩余天数/次数，冻结前先还电再申请，以便符合服务规则。  
- 作为渠道成员，我希望在「我的」看到渠道名与今日人天资格（预占/已确认），以便知晓能否换电。  
- 作为渠道成员，我希望预占失败时看到原因，并明确**不可换电**（持电池仅可还电、须渠道续配），以便联系渠道补额度。  
- 作为骑手，我希望运营商关跨网或信用停跨网时被明确拦截并提示原因，以便理解无法换电。  
- 作为骑手，我希望跨运营商换电成功后，后台换电单与我的订单记录一致（含三元组与跨网服务费），以便纠纷可追溯。  
- 作为骑手，我希望在订单查看换电、服务购买与退租/押金记录及空态，以便自助查历史。  
- 作为骑手，我希望完成实名认证、电池退还预约与客服拨号，以便合规使用与结束服务。

### 8. 站点合伙人

- 作为站点合伙人，我希望用独立账号登录，只读查看运营商为我配置的各站当前比例，以便知悉合作条款。（**已实现**）  
- 作为站点合伙人，我希望查看本人分润明细与可提现余额，并向运营商发起提现，以便收取场地分润。（**已实现**）

### 9. 品牌方（非本期）

- 作为品牌方，我不使用本后台管理运营设备（仅提供平台与用户端，非本期）。
