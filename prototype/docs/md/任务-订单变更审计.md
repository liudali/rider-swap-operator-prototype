# 任务：订单变更审计（变更记录）

> **这是什么**：订单与服务的「生命历程账」——谁在什么时间做了什么变更；**不是**再做一个订单列表。  
> **状态**：已拍板 · 原型 Mock 已上线。  
> **依据**：[竞品借鉴决策记录.md](./竞品借鉴决策记录.md) C-02 · [PRD.md](./PRD.md) · [acceptance-criteria.md](./acceptance-criteria.md)  
> **写法**：[业务文档写作规范](./业务文档写作规范.md)

## 业务设定

### 一句话

统一一个「变更记录」菜单，把套餐创建、冻结、消耗、跨网、退款等关键动作串成时间线，方便客服、渠道和对账说清「当时发生了什么」。

### 为什么需要

| 场景 | 没有变更记录 | 有变更记录 |
|------|-------------|-----------|
| 骑手投诉「没换电却扣人天」 | 多页翻查，说不清 | 时间线：预占 → 确认消耗 → 换电单 |
| 渠道质疑消耗偏多 | 无法按人解释 | 按团队/用户筛分配、消耗、收回 |
| 退款 / 冻结纠纷 | 难还原时点 | 冻结申请 → 审核 → 退款单串联 |
| 平台监管 | 只见结果 | 跨运营商事件可聚合查询 |

本质：**可追溯、可解释、可对账**。

### 谁能看、看到什么范围

| 角色 | 入口 | 能看什么 |
|------|------|----------|
| 平台管理员 | 侧栏「变更记录」 | 全平台（只读） |
| 运营商 | 侧栏「变更记录」 | 本运营商相关事件 |
| 渠道商 | 侧栏「变更记录」 | **仅本渠道成员**相关事件 |

各角色各一个入口，**不按事件类型拆多个菜单**。保留时长与订单同生命周期。

### 一期记哪些事

| 类型 | 记什么 | 一期 |
|------|--------|:----:|
| 个人套餐 | 订单创建、冻结、恢复、中途完结；关联换电单 / 电池 | ✅ |
| 渠道人天 | 持卡分配、确认消耗、分配 / 收回 | ✅ |
| 跨网 | 引用换电单（不重复记账） | ✅ |
| 可选 | 手动延期、套餐升级 | 二期 |
| 不做 | 纯界面点击、未影响计费的编辑 | ❌ |

### 页面怎么用

- 按关键词（手机 / 单号 / 摘要）、事件类型筛选。  
- 列表按时间倒序；展示变更前 → 变更后、操作人。  
- 关联单号可跳转到换电单、套餐单、退款管理。

### 和别的模块的边界

- 业务动作发生时**写入**审计事件；变更记录页只读聚合。  
- **不替代**套餐订单、换电订单、人天池等各自列表。  
- 运营商「信用评估」里的「变更记录」Tab 是**档位定档历史**，与本模块不同。

### 验收（白话）

- 平台 / 运营商 / 渠道侧栏都能进「变更记录」。  
- 运营商可按用户手机筛时间线。  
- 渠道只看见本渠道事件。  
- 关联单号能跳转换电 / 套餐 / 退款。  
- 真实 API 写入与各业务时间戳一致：开发联调项（原型已 Mock）。
