# 换电范围策略

> **这是什么**：运营商决定自己的用户**能不能去别的运营商柜子换电**，以及**别的运营商用户能不能来自己柜子换电**。  
> **本期不做**：给用户绑「主站点」或「只能在购套餐站换电」——**同一运营商下任意站点**都能购套餐、换电。  
> **叠加规则**：还要看平台「信用额度是否停跨网」，详见 [换电场景与运营商结算.md](./换电场景与运营商结算.md)。  
> **写法**：[业务文档写作规范](./业务文档写作规范.md)

## 业务设定

### 一句话

同运营商：想去哪站都行。跨运营商：两边的「允许跨网」都得开着，且用户所属运营商没被平台因信用停掉跨网。

### 两个概念

| 说法 | 含义 | 例子 |
|------|------|------|
| 同运营商换电 | 用户属于谁，柜子也是谁的 | 绿色出行用户在绿色出行任意站换电 |
| 跨网换电 | 用户所属运营商 ≠ 柜子所属运营商 | 绿色出行用户去陆家嘴运营商的柜子 |

用户「属于哪家运营商」：个人套餐看**卖套餐的那家**；渠道人天骑手看**卖额度的那家**。和扫码扫到哪一站**没有绑定关系**。

### 运营商只配一个开关：允许跨网换电

| | 说明 |
|--|------|
| 默认 | **开启** |
| 关掉之后 | **双向封闭**：① 本运营商用户不能去别人柜子；② 别人用户也不能来本运营商任意站 |

同运营商内部：**没有**「跨站开关」，也**没有**主绑定站拦截。

### 扫码时怎么判（顺序）

1. 是不是跨运营商？  
   - **否** → 允许（同运营商任意站）。  
   - **是** → 继续。  
2. 用户所属运营商是否允许跨网？不允许 → 拦截（己方关了跨网）。  
3. 柜子所属运营商是否允许跨网？不允许 → 拦截（对方拒外来）。  
4. 用户所属运营商是否因**信用额度用尽**被平台停跨网？是 → 拦截。  
5. 以上都过 → 允许跨网换电。

### 和平台管控怎么叠

| 谁关的 | 什么情况 | 影响 |
|--------|----------|------|
| 运营商自己关跨网 | 后台手动关 | 双向：自己人出不去，外人进不来 |
| 平台停跨网 | 保证金为 0 且信用额度用尽 | 只限制该运营商**自己用户出去**跨网（出站） |

### 后台与骑手端落位

| 端 | 位置 |
|----|------|
| 运营商后台 | 平台设置 / 站点相关里的 **换电范围设置**（跨网开关） |
| 骑手端 | 扫码换电被拦时，用失败提示说明原因 |

### 验收场景（白话）

| # | 场景 | 预期 |
|---|------|------|
| 1 | 本运营商用户，本运营商站点 A | 成功 |
| 2 | 本运营商用户，本运营商另一站点 B | 成功（同网任意站） |
| 3 | 本运营商用户去别家柜子，但本运营商关了跨网 | 失败：己方关跨网 |
| 4 | 别家用户来本运营商柜子，本运营商关了跨网 | 失败：拒外来 |
| 5 | 本运营商用户去外地运营商，但被平台信用停跨网 | 失败：信用停跨网 |
| 6 | 渠道人天骑手跨网，两边都开跨网且信用允许 | 成功；跨网设备费由额度售卖方承担相关规则；渠道池按日扣人天 |

## 实现附录（开发用）

> 业务读者可跳过。

### A. 准入流程图

```mermaid
flowchart TD
  A[换电扫码] --> B{跨运营商?}
  B -->|否 同运营商| OK[允许]
  B -->|是| C{用户运营商允许跨网?}
  C -->|否| X1[拦截: 运营商已关跨网]
  C -->|是| D{柜机运营商允许跨网?}
  D -->|否| X2[拦截: 站点运营商拒外来]
  D -->|是| E{用户运营商信用额度允许跨网?}
  E -->|否| X3[拦截: 信用额度用尽]
  E -->|是| OK
```

### B. 字段与拦截原因

| 字段 | 说明 |
|------|------|
| 运营商 ID | 配置主体 |
| 是否允许跨网 | 默认 true |
| 柜机站点 / 柜机运营商 | 扫码事实，非用户绑定 |
| 用户归属运营商 | 售卖方 / 额度售卖方 |
| 拦截原因 | 见下表 |

| 拦截原因（建议枚举） | 含义 |
|----------------------|------|
| 用户运营商关闭跨网 | 出站被拦 |
| 柜机运营商关闭跨网 | 拒外来 |
| 信用额度停跨网 | 平台管控 |

**本期废弃（不用）**：跨站开关、用户主绑定站、仅主站可换 等旧字段。
