# 渠道信用评估方案

> **这是什么**：人天池 / 设备租赁 / 激活码等模式下，渠道骑手电池（柜）押金算在**渠道商主体**上——平台怎么评信用、怎么抵扣应押、缺口怎么补。  
> **依据**：需求评审 C-01–C-05 · [渠道结算模式规则.md](./渠道结算模式规则.md) · [骑手电池押金.md](./骑手电池押金.md) · 文末决策索引

## 业务设定

### 一句话

这类渠道骑手默认**个人免缴押金**，应押责任统一算渠道；平台给渠道打分定抵扣额度，运营商可在此基础上改额度；不够的部分渠道线下打款，凭证由运营商审核。一期缺口以提醒为主（可配置是否停服）。

### 适用 / 不适用

| 适用 | 不适用 |
|------|--------|
| 人天池、设备租赁、激活码等「渠道统管骑手押金」 | **链接分销**（用户直购，走个人押金/免押） |
| — | 不替代个人用户的微信分 / 芝麻免押 |
| — | 不从批发款里自动扣押金（押金与采购分账） |

### 押金标准（平台统一）

| 设备 | 默认标准 | 谁改 |
|------|----------|------|
| 电池 | ¥3,000 / 块 | 仅平台管理员 |
| 换电柜 | ¥15,000 / 台 | 仅平台管理员 |

应押总额 ≈ 在服渠道骑手数 × 单骑手应押标准（默认按「1 块电池」；合同另有柜机分摊则按约）。  
信用能抵多少 = 不超过「应押」与「有效信用额度」的较小值；差额 = 渠道待补缴。

### 谁干什么

| 角色 | 职责 |
|------|------|
| 平台 | 定押金标准与评分/分级规则；新签手工初评；每月复评；结果给运营商 |
| 运营商 | 看评估；**可调高/调低信用额度**（填原因留痕）；审补缴凭证；收缺口提醒 |
| 渠道 | 看分、等级、额度、应押与缺口；提交线下打款凭证 |

### 评分与抵扣（可配置）

建议维度（权重可配）：合作年限、累计采购、消耗履约、押金历史、主体资质、第三方信用（一期可 Mock）。

示例等级（区间与比例均可改）：

| 等级 | 得分示例 | 抵扣比例示例 |
|------|----------|--------------|
| 优 | ≥ 85 | 100% |
| 良 | 70–84 | 60% |
| 中 | 55–69 | 30% |
| 差 | < 55 | 0% |

信用额度 ≈ 应押总额 × 该等级抵扣比例；运营商可手工改最终额度。

**初评**：新签不设默认等级，平台管理员签约时手工定级打分。  
**复评**：每月 1 日自动；采购额或骑手规模剧变可触发。运营商可向平台申诉复核。

### 缺口补缴

1. 系统发现待补缴 > 0 → 通知运营商（可抄送渠道）。  
2. 渠道线下打款后，在「渠道信用额度」交凭证（金额、流水号、转账日、附件）。  
3. 运营商审核：通过销账 / 驳回重提。  
4. 一期默认**不因缺口阻断换电**；「押金不足停服」可配置。连续久未补缴可升级提醒平台。

### 后台落在哪

| 页面 | 角色 |
|------|------|
| 平台 · 押金标准 / 信用规则 / 渠道商管理 | 平台管理员 |
| 渠道销售 → 签约详情（改额度） | 运营商 |
| 渠道信用额度（看数 + 交凭证） | 渠道 |
| 运营商总览（缺口 KPI、待审凭证） | 运营商 |

### 一期范围

模型、分级配置、初评/复评、调额、凭证审核、缺口展示与提醒均交付；外部征信可 Mock，规则须闭合。

## 实现附录（开发用）

> 业务读者可跳过。

### A. 公式与字段

```
应押总额 = activeChannelRiders × 单骑手应押标准
信用抵扣 = min(应押, creditLimit)
待补缴 = max(0, 应押 − 信用抵扣)
```

PlatformDepositStandard、CreditTierConfig、ChannelCreditProfile（含 platformLimit / operatorOverride）、ChannelDepositLedger、ChannelDepositPaymentProof。
