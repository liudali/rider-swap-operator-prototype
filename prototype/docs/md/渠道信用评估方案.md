# 渠道信用评估方案

> **这是什么**：人天池 / 设备租赁 / 激活码等模式下，渠道骑手电池（柜）押金算在**渠道商主体**上——平台怎么给额度、怎么抵扣应押、缺口怎么补。  
> **依据**：需求评审 C-01–C-05 · [渠道结算模式规则.md](./渠道结算模式规则.md) · [骑手电池押金.md](./骑手电池押金.md) · 文末决策索引  
> **写法**：[业务文档写作规范](./业务文档写作规范.md)  
> **一期口径（decision-098 / 099）**：界面**不展示信用分**；需信用渠道**默认初始信用额度 ¥100,000**，运营商可调整。**应押** = 签约运营商电池押金数额 × 渠道持电骑手数。评分/分级抵扣配置保留为后续能力，不作为一期操作入口。

---

## 业务设定

### 一句话

这类渠道骑手默认**个人免缴押金**，应押责任统一算渠道；平台给渠道默认初始信用额度（¥100,000），运营商可在此基础上改额度；不够的部分渠道线下打款，凭证由运营商审核。一期缺口以提醒为主（可配置是否停服）。信用分/等级一期不在后台展示。

### 适用 / 不适用

| 适用 | 不适用 |
|------|--------|
| 人天池、设备租赁、激活码等「渠道统管骑手押金」 | **链接分销**（用户直购，走个人押金/免押） |
| — | 不替代个人用户的芝麻信用免押 |
| — | 不从批发款里自动扣押金（押金与采购分账） |

### 应押怎么算（decision-099）

```
应押 = 签约运营商「定价管理 → 押金设置」电池押金数额
     × 该渠道当前持有电池的骑手数
```

| 项 | 口径 |
|----|------|
| 电池押金数额 | 运营商配置；关闭实缴时按 ¥0 |
| 持电骑手 | 人天池：在职且当前持电；设备租赁：白名单使用中且有电池 SN；其它：用户台账当前持电 |
| 不含 | 未持电在册骑手；换电柜押金（本期不并入应押） |

信用能抵多少 = 不超过「应押」与「有效信用额度」的较小值；差额 = 渠道待补缴。

### 谁干什么

| 角色 | 职责 |
|------|------|
| 平台 | 配置默认初始额度（一期固定 ¥100,000）；可选后续启用评分/分级规则 |
| 运营商 | 配置电池押金数额；看额度/应押/缺口；**可调高/调低信用额度**（填原因留痕）；审补缴凭证 |
| 渠道 | 看额度、应押与缺口；提交线下打款凭证 |

### 额度与抵扣（一期）

**默认初始额度**：需信用渠道签约生效时赋予 **¥100,000**（链接类除外）。  
**运营商调整**：可改最终额度，留痕。  
**公式**：

```
应押 = 运营商电池押金数额 × 持电骑手数
信用抵扣 = min(应押, 有效信用额度)
待补缴 = max(0, 应押 − 信用抵扣)
```

### 评分与抵扣（后续可选 · 一期不展示）

建议维度（权重可配）：合作年限、累计采购、消耗履约、押金历史、主体资质、第三方信用。

示例等级（区间与比例均可改）：

| 等级 | 得分示例 | 抵扣比例示例 |
|------|----------|--------------|
| 优 | ≥ 85 | 100% |
| 良 | 70–84 | 60% |
| 中 | 55–69 | 30% |
| 差 | < 55 | 0% |

若后续启用：信用额度 ≈ 应押总额 × 该等级抵扣比例；可覆盖默认初始额度策略。

**初评（后续）**：新签不设默认等级，平台管理员签约时手工定级打分。  
**复评（后续）**：每月 1 日自动；采购额或骑手规模剧变可触发。运营商可向平台申诉复核。

### 缺口补缴

1. 系统发现待补缴 > 0 → 通知运营商（可抄送渠道）。  
2. 渠道线下打款后，在「渠道信用额度」交凭证（金额、流水号、转账日、附件）。  
3. 运营商审核：通过销账 / 驳回重提。  
4. 一期默认**不因缺口阻断换电**；「押金不足停服」可配置。连续久未补缴可升级提醒平台。

### 后台落在哪

| 页面 | 角色 |
|------|------|
| 平台 · 押金标准 /（后续）信用规则 / 渠道商管理 | 平台管理员 |
| 渠道销售 → 签约渠道（额度列，无信用分）· 调整额度 | 运营商 |
| 渠道信用额度（看数 + 交凭证，无评分 KPI） | 渠道 |
| 运营商总览（缺口 KPI、待审凭证） | 运营商 |

### 一期范围

默认初始额度、调额、凭证审核、缺口展示与提醒均交付；**信用分与分级抵扣 UI 不交付**（decision-098）。外部征信可 Mock。
