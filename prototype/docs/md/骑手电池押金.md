# 骑手电池押金（运营商实收）

> **这是什么**：骑手使用电池时交给**运营商**的押金（或信用免押），不是运营商交给平台的「服务保证金」。  
> **依据**：[decision-005](../decisions/decision-005.md)（收押）· [decision-006](../decisions/decision-006.md)（退押）· [decision-007](../decisions/decision-007.md)（数额）· [decision-050](../decisions/decision-050.md)（C 端环节）· [decision-073](../decisions/decision-073.md)（免押门槛·历史）· [decision-100](../decisions/decision-100.md)（仅芝麻）· [decision-076](../decisions/decision-076.md)（申请退押）· [decision-086](../decisions/decision-086.md)（用户押金台账）

## 业务设定

### 一句话

骑手要用电瓶，要么**交一笔押金**，要么用**芝麻信用免押**；这笔钱进运营商，**不参与**平台抽成和站点分润。退押走「退款管理」，和退套餐可以分开设置。**本期不支持微信支付分免押**（decision-100）。

### 和「平台保证金」的区别

| | 骑手电池押金 | 平台服务保证金 |
|--|--------------|----------------|
| 谁付给谁 | 骑手 → 运营商 | 运营商 → 平台 |
| 干什么 | 约束还电、损坏等 | 清分、信用、提现等 |
| 后台大概在哪 | 用户 / 用户押金 / 退款管理 | 平台服务 · 服务保证金账户 |

### 什么时候要办押金

1. **个人买套餐**：和套餐**同一笔支付**里完成——交押金，或走信用免押（免押则押金实付为 0）。
2. **渠道人天骑手**：在**第一次领电池之前**必须办完交押或免押；没办完不能出电。办完后记「实付」或「信用免押」，不再用静默的「渠道担保」顶替（设备租赁等另有渠道信用规则）。

### 用户怎么选

- **信用免押**：芝麻信用达标即可；记为「信用免押」，运营商实收 0 元。  
- **支付押金**：按运营商「押金设置」里的金额实缴；记为「实付」，状态为「在押」。  
- **未达标**：必须实缴。

免押门槛由**平台统一规定**（芝麻信用 ≥500），运营商在「押金设置」页只能看、不能改；运营商可配置的是**押金金额**和是否启用。

### 押金有哪些类型（怎么理解）

| 你在后台看到的 | 含义 | 算进「在押总额」吗 |
|----------------|------|-------------------|
| 实付 · 在押 | 已交钱、电池相关责任还在 | 算；可申请退押 |
| 实付 · 退押中 | 已申请退、钱还没退完 | 仍算在账上 |
| 实付 · 已退押 | 已退还 | 不算 |
| 信用免押 | 没交钱，用信用额度免押 | 不算 |
| 渠道担保 | 少数渠道承担押金责任的场景 | 不算（另见渠道信用） |
| 无需 / —— | 本单无押 | 不算 |

### 钱怎么分

- 押金**不参与**平台服务费抽成，也**不参与**站点合伙人分润。  
- 只有**套餐实付**才参与上述切分。

### 怎么退押

1. **前提**：电池已还；且有一笔「实付 · 在押」押金。  
2. **入口**：统一在 **退款管理**（类型为「押金退还」），与套餐冷静期/中途完结退款同一列表，但规则独立。  
3. **自动还是手动**：运营商在「退款设置」里单独选押金是「自动退款」还是「手动确认」（可与套餐退款模式不同）。  
   - 自动：条件满足后系统按原支付路径退回。  
   - 手动：进入待审核，运营确认后再退。  
4. **影响**：只退押金，**不会**因此把套餐中途完结，服务期照常。  
5. **若主单退款里带着押金**：随主单一起处理，不再单独受「押金自动/手动」开关拆开。

### 骑手端要让用户看见什么

| 场景 | 用户看到什么 |
|------|----------------|
| 购套餐 | 选完套餐后出现「免押 / 交押金」二选一，并展示「套餐费 + 押金 = 应付合计」，再确认支付 |
| 渠道首次领电 | 若还没办押金，先办免押或缴押，再允许领电 |
| 我的 | 展示押金方式与状态；实付且已还电时可申请退押 |

### 各后台落在哪

**运营商 · 订单与服务 → 用户押金**

- 只展示**实付押金**流水；**不跟某一笔套餐强绑定**。  
- 同一用户可以有多条（例如换运营商：旧押退掉，再交新押）。  
- 列：流水号、用户、金额、状态、支付时间、退款时间。  
- 操作：退款日志（各节点：入账、申请、还电校验、审核、原路退等及时间）。

**运营商 · 用户**

- 看在押总额、在押人数、信用免押人数、渠道担保人数等。  
- 列表可按电池押金类型筛选。  
- 套餐详情里清分表仍标注「押金不切分」。

**平台 · 用户管理**

- **用户信息**：用户表上区分押金方式、押金状态等。  
- **用户押金统计**：按运营商汇总在押、免押、渠道担保、退押中等。

## 实现附录（开发用）

> 业务读者可跳过本节。字段名、模式码、决策索引集中于此。

### A. 退押模式

| 配置项 | 取值 | 行为 |
|--------|------|------|
| 押金退款模式 | 自动 | 条件满足后原路退至运营商子商户收款路径 |
| 押金退款模式 | 手动 | 待审核，确认后系统执行退款 |

（实现侧历史字段名：`depositRefundMode` = `auto` / `manual`，与套餐退款模式配置相互独立。）

### B. 退款队列

- 押金退还与冷静期/中途完结等同处退款管理列表。  
- 业务类型展示名：**押金退还**（实现侧可对应类型枚举「押金退还」）。

### C. 用户押金台账（decision-086）

- 粒度：每笔**实付**一条；不含信用免押行。  
- 无套餐单强制外键；换运营商允许多条。  
- 状态：在押 / 退押中 / 已退押。  
- 操作：退款日志节点链（入账 → 申请 → 还电校验 → 审核 → 原路退等）。

### D. 免押门槛（decision-073）

- 芝麻信用 ≥ 500；运营商只读（decision-100；已移除微信支付分）。  
- 押金数额与启停：运营商「平台设置 → 押金设置」。
