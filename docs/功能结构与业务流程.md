## 业务设定

### 一句话

本后台管运营主体与账，不管物联网硬件本身：骑手在用户端付钱/用人天换电；钱进运营商收款账户，平台拿约 1% 技术服务费；渠道批发人天、合伙人按站分润、融资放款是支线。

### 怎么读本文

1. 先看「系统边界」与「谁跟谁有关系」。  
2. 再看「按登录身份有哪些能力」（能力地图）。  
3. 核心流程用白话记住目标与异常，细则与图放附录。  
4. 评审演示更建议跟 [业务整体预览图.md](./业务整体预览图.md) 的「购套餐 8 步脊柱」。

### 系统边界（白话）

| 在体系外 / 由平台能力承接 | 本后台经营主体 |
|---------------------------|----------------|
| 骑手用户端、物联网、智格平台清分能力 | 运营商、渠道商、资金方、运营员工、站点合伙人 |

骑手支付进运营商；渠道向运营商采购人天；资金方与运营商做资产融资协作；平台向运营商收约 1% 技术服务费。

### 组织关系（白话）

- 智格平台：技术 + 约 1% 服务费。  
- 资金方：资产融资放款（台账）。  
- 渠道：批发采购人天，团队骑手来运营商柜子换电。  
- 运营商：按站给站点合伙人分润；内部有运营员工。

### 能力地图（按登录身份）

**经营主体登录**可进入：平台管理员、运营商、渠道商、资金方、站点合伙人各自菜单。  
**员工登录**：按勾选权限裁出菜单，数据只见所属主体。

| 身份 | 大致能管什么 |
|------|----------------|
| 平台管理员 | 总览、用户、订单、设备、渠道监管、流水、平台账户、运营商治理、保证金、跨网统价 |
| 运营商 | 总览、定价、渠道销售、站点与合伙人、设备、融资、订单、流水、平台服务、员工、用户、收款账户 |
| 渠道商 | 总览、人天额度池（或按模式：链接/租赁/激活码）、员工 |
| 资金方 | 总览、员工、放款申请、收款账户 |
| 站点合伙人 | 总览、我的站点、分润明细、提现结算、收款账户（只读配置） |

运营商侧常见模块：平台设置（城市底价、换电范围）、站点（信息、场费电费、合伙人）、设备、融资、订单与服务（套餐/换电/冻结/退款）、流水三台账、平台服务（保证金/服务费/往来）、员工、用户、收款账户。

### 核心流程索引（白话结论）

| 流程 | 记住什么 |
|------|----------|
| 支付 → 清分 → 摊销 | 支付成功就清分；包月按日摊销只给站点/收入分析用，不再打第二笔款 |
| 换电与归因 | 换电记事实与过程；收入按摊销/当笔归因，**不二次打款** |
| 跨网清分 | 跨网设备费平台代收代付；平时先扣保证金 |
| 保证金充值 | 运营商对公打款 → 平台确认 → 恢复「保证金优先」 |
| 站点合伙人分佣 | 按站绑定；同人多站可不同比例 |
| 换电范围 | 运营商可关跨网（双向封闭） |
| 员工登录 | 菜单与数据按权限裁 |
| 套餐生命周期 | 冻结停确认；中途完结要冲正应分 |
| 融资 | 仅融资台账；已无「设备直租」租金轨道 |
| 次卡/超次 | 当笔确认、当笔分账（与包月摊销并存） |
| 三台账 | 资金实收 ≠ 清分 ≠ 提现 ≠ 收入摊销，不可混列 |
| 企业天数池 | 渠道批发 → 分配 → 消耗扣天；采购时结清，消耗不再给运营商打款 |

### 支付成功后钱怎么走（白话）

1. 骑手买包月/次卡，款进运营商收款账户；同时平台约 1% + 运营商约 99% 实时分出。  
2. 服务期内：包月按日确认收入（台账）；每次成功换电写换电单。  
3. 提现：运营商申请 → 平台审核 → 打到绑定账户（一期提现不扣融资待还，预留二期）。  
4. 中途退款：运营商原路退；平台 1% 一般不退；若已提现且余额不够 → 须垫付。

### 换电成功后发生什么（白话）

套餐须在服务中且未冻结。成功后记用户归属运营商、柜机归属、电池归属；若柜机或电池不是用户归属方的，产生跨网设备费，经平台日清。包月不因换电再打款；次卡则当笔已在支付时清分。

### 套餐状态（白话）

| 状态 | 骑手 | 电池 | 收入确认 | 换电 |
|------|------|------|----------|------|
| 服务中 | 可换电 | 换电后可持有；申请冻结前须还电 | 按日确认 | 正常 |
| 已冻结 | 不可换电 | 不持有 | 建议暂停确认 | 拒新换电 |
| 待领取电池 | 须扫码领电 | 不持有 | 按日确认 | 仅出电 |
| 中途完结 | 服务终止 | 不持有（退款前已还电） | 停未到期并冲已确认 | 停止 |
| 待首换开通 | 未首换 | 不持有 | — | 首次换电后开通 |
| 已完结 | 到期 | 须已还电 | 确认至服务末日 | — |

### 渠道四种结算模式（一眼）

| 模式 | 渠道买什么 | 用户怎么获得权益 | 平台约 1% 何时计 |
|------|------------|------------------|------------------|
| 人天池 | 人天额度 | 登记并分配人天 | 确认消耗 |
| 渠道分销 | 无批发购卡 | 推广链接/二维码购套餐 | 支付成功 |
| 设备租赁 | 统一月租 | 白名单购渠道套餐 | 月租 + 购套餐 |
| 激活码 | 激活码 | 输入码核销 | 码核销 |

设备租赁欠费停服：白名单可还电、不可出电，提示续费。

### 菜单与角色速查（白话）

平台独有：用户/订单/设备/渠道监管/全平台流水/平台账户/运营商治理/保证金/统价。  
运营商独有：定价与渠道销售、站点与合伙人配置、设备、订单流水、往来与保证金、融资、本站用户、收款账户。  
渠道：按模式看人天池或链接/租赁/激活码。  
资金方：放款申请。  
站点合伙人：门户只读 + 提现申请。  
员工：按权限。

### E. 架构 B：支付 → 清分 → 摊销（时序）

前置：站点已绑定 `device_owner_id`；收款账户进件完成。

| 阶段 | 步骤 | 后台可见（运营商） | 资金侧 |
|------|------|-------------------------|--------|
| ① 收款+清分 | 骑手购买包月/次卡，支付成功 | 资金实收；清分明细「已清分」 | 平台 1% + 运营商 99% 实时分出 |
| ② 服务期 | 按日（包月）或当笔（次卡）确认收入 | 运营商内部收入台账 | 无二次打款 |
| ③ 换电 | 每次成功换电写入换电单 | 订单与服务 → 换电订单 | 无 |
| ④ 提现 | 运营商申请 → 平台审核 → 打款 | 提现申请 | 一期不扣融资待还 |
| ⑤ 退款 | 中途退款：运营商子商户原路退 R | 资金实收 −R；清分冲正 | 平台 1% 不退；已提现 → 须垫付 |

```mermaid
sequenceDiagram
  participant R as 骑手
  participant App as 用户端
  participant IoT as 物联网
  participant Mch as 运营商子商户
  participant Plat as 平台商户
  participant BO as 运营后台
  R->>App: 选站点/柜机购买套餐
  App->>Mch: 支付 P（架构 B）
  Mch->>Plat: 实时分账 1%
  Mch->>BO: 资金实收 +P
  BO->>BO: 清分明细 已清分（运营商 99%）
  loop 服务期内（包月按日）
    BO->>BO: 收入台账 recognition_date 确认 P/D
    R->>App: 扫码换电
    App->>IoT: 开门/换电指令
    IoT-->>BO: 换电成功 → SwapOrder
  end
  alt 运营商提现
    Mch->>BO: 提现明细 已提现
  else 中途退款 R
    App->>Mch: 原路退 R（运营商出款）
    Mch->>BO: 资金实收 −R
    BO->>BO: 停止未到期确认；清分/收入冲正
    Note over BO: 已提现且余额不足 → 须垫付
  else 服务冻结
    Note over BO: 冻结期间不确认收入（建议）
  end
```

异常：支付成功但设备未入网 → 不计费，待认证后补记或拒单；有效站/SLA 未达标 → 可冻提现或新单清分（政策可选）；平台 SaaS 费与运营清分分表。

### F. 换电订单与收入归因

成功换电生成 `SwapOrder`（关联套餐/额度池、柜机、格口、SOC；写入 `userOwner` / `cabinetOwner` / `batteryOwner`）。跨网费：U→C、U→B 经平台日清。

```mermaid
flowchart TD
  A[骑手扫码] --> B{套餐服务中且未冻结?}
  B -->|否| Z[换电失败/拒绝]
  B -->|是| C[用户端下发换电]
  C --> D[物联网执行柜机指令]
  D --> E{设备反馈成功?}
  E -->|否| Z2[失败+过程日志]
  E -->|是| F[换电订单成功]
  F --> G[过程日志]
  F --> T[三元组 U/C/B + 跨网设备服务费]
  T --> H[关联当日收入摊销份额]
  H --> I[收入台账更新 · 清分状态保持已清分]
```

| 对象 | 字段/规则 |
|------|-----------|
| 套餐单 | `valid_from` / `valid_to`、`swap_used`、`accrued`、`payout=已清分` |
| 换电单 | 必须 `package_order_id`；`pay` 常为 0（包月内含） |
| 清分 | 支付成功即已清分；换电不触发额外打款 |

### M. 次卡 vs 包月 · 三台账

| 对比项 | 包月套餐 | 次卡 / 超次另付 |
|--------|----------|-----------------|
| 收入确认 | 按日摊销 `P/D` | 换电成功当笔 |
| 清分时机 | 支付成功实时清分（1B） | 支付成功实时清分 |
| 订单号 | `PackageOrder` | 独立订单号 |

| 台账 | 含义 | 菜单 |
|------|------|------|
| 资金实收 | 子商户实收实付 | 我的流水 → 资金实收 |
| 清分明细 | 支付分账与退款冲正 | 我的流水 → 清分明细 |
| 提现明细 | 运营商提现记录 | 我的流水 → 提现明细 |
| 收入台账 | 运营商主体摊销 | 内部报表 |

```mermaid
flowchart LR
  PAY[骑手支付] --> CASH[资金实收 +]
  PAY --> SPLIT[清分明细 已清分]
  SPLIT --> WD[运营商提现]
  WD --> PO[提现明细]
  PAY --> REV[收入台账 按日摊销]
  SWAP[换电成功] --> REV
  REF[退款] --> CASH2[资金实收 −]
  REF --> SPLIT2[清分冲正]
  REF --> REV2[收入冲减]
```

退款：运营商原路退；平台 1% 不退；已提现不足 → 须垫付。
