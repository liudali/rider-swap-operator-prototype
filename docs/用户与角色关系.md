# 用户与角色关系

> **这是什么**：骑手（C 端用户）与平台内各经营主体之间，**关系是什么、何时建立、何时解除、解除后什么还留着**。不含平台管理员、租赁公司（资方）与运营员工。  
> **依据**：[用户-运营商归属模型.md](./用户-运营商归属模型.md) · [天数池.md](./天数池.md) · [渠道结算模式规则.md](./渠道结算模式规则.md) · [个人套餐定价与退款.md](./个人套餐定价与退款.md) · [站点合伙人.md](./站点合伙人.md) · decision-090  
> **写法**：[业务文档写作规范](./业务文档写作规范.md)

## 业务设定

### 一句话

骑手在智格只有**一个平台账号**；与运营商是**商业归属**，与渠道是**按模式不同**（组织成员 / 链接归因 / 白名单 / 码核销）；与站点合伙人**没有直接档案关系**，只在个人换电确认收入时按站点间接分润。

### 怎么读下表

| 列 | 含义 |
|----|------|
| 关系性质 | 档案绑定 / 会话或订单标记 / 权益来源 / 无直接关系 |
| 建立 | 谁、在什么动作下、写入什么 |
| 解除 | 谁、在什么动作下、立即还是到期失效 |
| 解除后保留 | 历史订单、审计、佣金、押金等是否仍可查 |

### 总览矩阵

| 对象角色 | 与用户的关系性质 | 建立（触发） | 解除（触发） | 解除后仍保留 |
|----------|------------------|--------------|--------------|--------------|
| **智格平台** | 平台身份（登录账号） | 注册/首次登录 | 账号注销 `[待确认]` | 合规留存期内订单与审计 |
| **运营商** | 商业归属 `userOwner` | 个人购套餐支付成功；激活码核销；等权益开通规则 | 无「解绑运营商」；随套餐/服务完结或换运营商新购覆盖 | 历史订单、押金台账、变更记录 |
| **客户·人天池** | 组织成员 + 人天权益 | 渠道在「骑手登记」建档并编入团队 → 分配人天开通 | 渠道标记**离职**：停服 + 剩余天数回池 | 登记与消耗历史、分配/回池流水 |
| **分销商·链接类** | 订单级渠道归因（非永久绑定） | 24h 内点击链接后**首笔**购卡（无在服套餐、无历史个人购卡） | 归因窗口过期未购；续费/再次购卡改正式价；首笔成交后订单永久带 `channel_id` | 已成交订单的渠道标记与佣金对账 |
| **客户·设备租赁** | 白名单成员（二期） | 渠道加入白名单（免费/付费） | 移出白名单；或渠道主体停用 | 历史白名单订单（付费型） |
| **分销商·激活码** | 码核销开通的服务（二期） | 用户输入有效码核销一次 | 服务随套餐到期/规则终止；码本身不可复用 | 核销记录；一码永久 consumed |
| **站点合伙人** | **无**用户档案关系 | — | — | 个人换电确认收入按**站点**切分时间接关联 |

> **不含**：平台管理员（治理后台）、租赁公司/资金方（B2B 融资）、运营员工（主体内部账号）。

## 分角色说明

### 1. 智格平台 · 平台身份

| 项 | 规则 |
|----|------|
| 关系 | 同一手机号/微信对应一个骑手账号，贯穿所有运营商与渠道场景 |
| 建立 | 用户端注册或首次授权登录 |
| 解除 | 账号注销流程 `[待确认]`：是否允许有在服套餐/在押押金时注销 |
| 备注 | 平台身份 ≠ 商业归属；退登只清会话，不清 `userOwner` |

### 2. 运营商 · 商业归属

详规见 [用户-运营商归属模型.md](./用户-运营商归属模型.md)。

| 项 | 规则 |
|----|------|
| 关系 | **商业归属** = 售卖/收款/清分/退款主体（`userOwner`）；用户**不绑定**具体站点 |
| 建立 | **支付成功**写入（个人购套餐、链接专享价购套餐等）；激活码核销、部分渠道权益开通按各模式规则写入 |
| 变更 | 向**另一家运营商**成功购新套餐 → 归属切到新运营商；旧运营商下未完结服务/押金按各自规则处理 |
| 解除 | **没有**「解除与运营商关系」的单独操作；随服务完结、退款终止、或新归属覆盖而结束当前归属下的在服状态 |
| 会话层 | 购前 `context_operator_id` 可因扫柜/定位/链接变化；**支付页禁止切换**，防串单 |

**与个人骑手**：自费购套餐 → 支付成功建立/更新归属。  
**与渠道骑手（人天池）**：商业归属仍为**额度售卖方运营商 U**；渠道是组织与额度来源，不是 `userOwner`。

### 3. 客户·人天池 · 组织成员与人天权益

详规见 [天数池.md](./天数池.md)。

| 项 | 规则 |
|----|------|
| 关系 | 双层：**组织成员**（登记在渠道团队）+ **人天权益**（分配额度后的在服状态） |
| 建立 · 成员 | 渠道「骑手登记」建档 → 编入团队（团队绑定消耗池） |
| 建立 · 权益 | 「额度分配」给人加天 → **分配即开通**服务（首版） |
| 变更 | 换团队、调额度：在渠道侧操作；不自动改 `userOwner` |
| 解除 · 离职 | 渠道标记**离职**（在职/离职均可管理团队，见 decision-051）→ **立即**：停服、未用人天**强制回池**、**不退骑手零钱** |
| 解除 · 仅收回额度 | 分配页收回天数 → 服务收回；若仍留职则仍是组织成员 |
| 解除后 | 组织登记可标离职留档；消耗/分配/回池流水可查；用户仍可用同一平台账号走个人购套餐路径 |

**额度耗尽**：不是「解除关系」，但换电阻断，须还电进入待还电态，直至渠道续配。

### 4. 分销商·链接类 · 归因（非永久绑定）

详规见 [渠道结算模式规则.md](./渠道结算模式规则.md) 模式二。

| 项 | 规则 |
|----|------|
| 关系 | **订单级**渠道来源标记；用户档案上**无**「我是某分销商成员」 |
| 建立 | 首次点击/扫码**有效推广链接** → 开启 **24h 归因窗口** → 窗口内**首笔**购授权套餐（无在服个人套餐、无历史个人购卡成交）享专享价并记 `channel_id` + 首触 `link_id` |
| 不适用专享价 | **续费**（在服个人套餐）或**再次购卡**（曾成交个人购卡）→ 运营商**正式零售价**，不写新渠道佣金 |
| 窗口内 | 再点**同渠道**其他链接：**不**重置 24h；点**其他渠道**链接：按最后触达**重置** 24h（仍仅首笔未购可享专享价） |
| 解除 · 未成交 | 24h 过期未支付 → 恢复正式零售价，无渠道标记 |
| 解除 · 已成交 | 首笔成交后无「解除归因」；该订单永久保留渠道字段；后续购卡不再享专享价 |
| 与运营商 | 归属运营商 = 链接锁定的签约运营商；渠道标记**不改变** `userOwner` |

### 5. 客户·设备租赁 · 白名单（二期）

| 项 | 规则 |
|----|------|
| 关系 | 专属站点下的**白名单成员**；分免费（月租覆盖）与付费（须购白名单套餐） |
| 建立 | 渠道在「白名单」添加用户（手机号等） |
| 解除 · 主动 | 渠道移出白名单 → 不可在该专属站取电，**仍可还电** |
| 解除 · 被动 | 运营商**停用渠道主体** / 欠月租停服 → 名单内不可取电，仍可还电；提示联系管理员 |
| 与运营商 | 免费白名单：归属仍为签约运营商；**付费**白名单套餐款进**渠道子商户**，订单 `seller_channel_id` 见专文 |
| 解除后 | 付费型历史订单仍在「白名单订单」；运营商退款管理**不处理**该笔 |

### 6. 分销商·激活码 · 核销开通（二期）

| 项 | 规则 |
|----|------|
| 关系 | **一次性**码 → 开通一段套餐服务；非组织成员关系 |
| 建立 | 用户输入有效码 → **核销成功** → 套餐开通，归属签约运营商；**不经在线付款** |
| 解除 | 服务随套餐自然到期或按退款/终止规则结束；**码永久 consumed，不可再次核销** |
| 解除后 | 「核销记录」可查；平台 1% 已在核销时计提 |

### 7. 站点合伙人 · 无直接用户关系

详规见 [站点合伙人.md](./站点合伙人.md)。

| 项 | 规则 |
|----|------|
| 关系 | 用户**不**与合伙人建档、绑定或登录关联 |
| 间接关联 | 个人用户在**某站点**换电且产生**已确认可分配收入**时，按该站合伙人比例从运营商份额切分 |
| 建立/解除 | 由运营商在「站点 × 合伙人」配置添加/解绑；**立即生效**，不回溯历史 |
| 不算分润 | 渠道人天、设备租赁白名单、跨网设备费 |

## 多关系并存与优先级

同一骑手账号在同一时期可能同时存在：

| 并存组合 | 说明 |
|----------|------|
| 平台身份 + 运营商归属 + 个人套餐 | 最常见个人路径 |
| 平台身份 + 运营商 U + 人天池组织成员 | 渠道骑手；换电走人天，不走个人套餐 |
| 个人套餐 + 链接归因订单 | 仅该笔订单带渠道标记；不改变归属 |
| 人天池 + 个人套餐 | **已取消**应急自费套餐兜底；额度不足只能还电，不能自费切换 |
| 白名单 + 个人套餐 | 租赁专属站场景；付费白名单须购渠道套餐 |

**换电校验优先级**（白话）：先看是否有权在该站换电（白名单/范围）→ 再看权益来源（个人套餐 / 人天额度 / 次卡等）→ 再看押金与跨网。详见 [渠道骑手可换电校验.md](./渠道骑手可换电校验.md)。

## 典型「解除」场景对照

| 用户动作 / 业务动作 | 受影响关系 | 结果 |
|---------------------|------------|------|
| 个人套餐冷静期/中途退款成功 | 运营商在服套餐 | 服务终止；押金按规则退；归属仍可为原运营商直至新购 |
| 向新运营商购套餐成功 | 运营商归属 | `userOwner` 切到新运营商；旧押金额外台账处理见押金专文 |
| 渠道标记骑手离职 | 客户·人天池 | 停服 + 天数回池；用户账号仍在 |
| 收回全部人天但未离职 | 人天权益 | 无额度换电；组织成员身份仍在 |
| 24h 归因过期未付 | 分销商·链接类 | 仅失去专享价；无订单则无永久标记 |
| 移出白名单 | 客户·设备租赁 | 不可取电，可还电 |
| 运营商解绑站点合伙人 | 站点合伙人 | 只影响**之后**该站个人收入的分润，与用户无感 |

### A. 建议字段/状态

| 关系 | 建议字段 | 建立事件 | 解除/终止事件 |
|------|----------|----------|---------------|
| 平台身份 | `user_id` | `USER_REGISTERED` | `USER_DEACTIVATED` |
| 运营商归属 | `userOwner` / `seller_operator_id` | `PAYMENT_SUCCESS` / `CODE_REDEEMED` | 无单独事件；`SERVICE_ENDED` / 新 `PAYMENT_SUCCESS` 覆盖 |
| 人天池成员 | `channel_rider.status`：在职/离职 | `RIDER_REGISTERED` | `RIDER_OFFBOARDED` |
| 人天权益 | `quota_remaining` + 在服标记 | `QUOTA_ALLOCATED` | `RIDER_OFFBOARDED` / `QUOTA_RECLAIMED` / 消耗至 0 |
| 链接归因 | `attribution_start` + `channel_id` | `LINK_ATTRIBUTED` | `ATTRIBUTION_EXPIRED`；订单 `ORDER_PAID` 永久写 `channel_id` |
| 白名单 | `whitelist_entry.status` | `WHITELIST_ADDED` | `WHITELIST_REMOVED` / `CHANNEL_SUSPENDED` |
| 激活码 | `code.status`：未用/已核销 | `CODE_REDEEMED` | 码不可复用；服务 `SERVICE_ENDED` |
| 合伙人 | 无用户 FK | — | —；分润依赖 `site_id` + 订单/换电确认事件 |
