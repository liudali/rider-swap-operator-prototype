# 运营商 · 逾期管理 PRD

> 版本：V1.2  
> 日期：2026-09-15  
> 阶段：MVP  
> 决策：[decision-136](../../../decisions/decision-136.md) · [decision-142](../../../decisions/decision-142.md)（展示 / 暂不封顶）· [decision-143](../../../decisions/decision-143.md)（先付后还 / 减免 / 不分润）  
> 配套原型：`../prototype/index.html`（独立演示）· 主后台 `prototype/index.html` → 订单与服务 → **逾期管理**  
> 验收标准：`../acceptance-criteria.md`

## 1. 结论

运营商增加独立模块 **逾期管理**。只收录「手里还有电池、但权益已经没了」的用户，并按权益来源拆成两条账：

| 类型 | 谁 | 怎么算 | 钱/额度从哪出 |
|------|----|--------|----------------|
| **个人套餐逾期** | 套餐到期或次数耗尽仍持电 | `逾期天数 × 日费 x`；不足一天按一天；**暂不封顶** | 骑手承担；**须先付清占用费才能进入还电**；运营商可改本单应付（含 0） |
| **人天池占用** | 个人剩余人天 = 0 仍持电 | 不足一天按 1 人天 | **从签约渠道的额度池可用余额扣**，不向骑手收现金 |

两条账必须在列表上能一眼分开。链接类用户走个人套餐逾期，不走人天池占用。

## 2. 背景

- 正常预期：服务结束应还电池。
- 现状：骑手端已能「仅还电」；运营商没有名单、没有计费、渠道零额度持电也不再扣池（decision-049 旧口径）。
- 资产在运营商，经营主体也是运营商，所以模块放在运营商，不放平台、不放渠道主菜单。

## 3. 产品判断

- **俞军**：不还电的代价从「0」变成「按日计」，替换成本清晰。人天池代价落在渠道池，避免骑手被双计（既无服务又交现金）。
- **乔布斯**：一个模块、两个 Tab、一套设置。不做罚没、远程锁电、自动续购。
- **支持**：电池周转可管；渠道对自己骑手的占用负责。
- **反对**：客诉与「占用费」法务表述；池扣成负数会逼渠道紧急增购。
- **失效**：监管认定日费不合理；或渠道因欠人天大批停服导致运力事故。

## 4. 假设与待确认

| 项 | 口径 | 标记 |
|----|------|------|
| 日费金额 | 运营商在本模块配置，演示默认 **¥10 / 天** | `[假设]` 正式默认值跟运营确认 |
| 宽限期 | **0 天**，进入逾期即起算 | 用户未提宽限 |
| 天数算法 | `ceil(持电逾期小时数 / 24)`，最小 1 | 不足一天按一天 |
| 个人扣款顺序 | **先付清占用费，再进入还电**；押金不抵占用费（仍在押至还电后退）；**暂不封顶** | 已锁定 · decision-143（覆盖 142 还电不拦 / 押金抵） |
| 减免 | 0 ≤ 改后应付 ≤ 系统计费；改为 0 = 已结清可直接还电；每次必填原因并写日志 | 已锁定 · decision-143 |
| 分润 | 占用费全额进运营商资金实收，不抽平台 1%、不切合伙人、不进清分明细 | 已锁定 · decision-143 |
| 付清后计费 | 付清或减免为 0 后至还电成功，不再加收占用费 | `[假设]` |
| 付款后还电失败 | 已付不退；可再次进入还电，无需再付 | `[假设]` |
| 免押 / 未结清 | 未结清占用费限制新购套餐；未付清不可还电 | `[假设]` 新购拦截 |
| 人天起算 | 剩余变为 0 且仍持电；**当日若已按「日终持电」扣过 1 人天，当天不重复扣逾期占用**，次日起扣 | 与 decision-126 对齐 |
| 池余额不足 | 允许扣成负数，记「欠人天」，渠道须增购补平 | `[假设]` |
| 平台 1% | 人天逾期占用按「确认消耗-持有电池」向售卖方计提；个人占用费现金**不抽成** | 已锁定 · decision-143 |
| 平台后台 | 一期不单独做逾期列表 | 平台可在用户详情只读看到状态 |

## 5. 进入与退出

### 5.1 进入（同时满足）

1. 当前 **持有电池**；
2. 且下列之一：
   - 个人套餐：`valid_to` 已过，或次卡/单次次数耗尽，服务状态不再是「服务中 / 待激活 / 已冻结」；
   - 人天池：在职，个人剩余人天 = 0。

冻结中持电：已有「持电不可冻结」。本模块不收录冻结单。

### 5.2 退出

个人：发起支付（或运营改价）时锁定应付 → **付清或应付 = 0** 后才允许扫码还电 → 还电成功出「进行中」，进「已完结」。未付清不可进入还电流程。  
人天池：仍可直接还电；渠道再分配使剩余 ≥ 1 → 退出占用、恢复可换电；已扣人天不退。  
个人：逾期中续费/新购 → 须先还电且占用费已结清。

### 5.3 门禁（骑手端）

`allowed_swap = false`。

| 类型 | `allowed_return` | 说明 |
|------|------------------|------|
| 个人套餐逾期 · 占用费未结清 | **false** | 先支付占用费（或运营减免为 0） |
| 个人套餐逾期 · 已付清 / 应付 = 0 | true | 进入扫码还电 |
| 人天池占用 | true | 不收现金 |

原因枚举：

- 个人未结清：`套餐已结束·请先支付占用费`
- 个人已结清：`套餐已结束·待还电`
- 人天：`个人无额度·待还电`（沿用 E006）

### 5.4 骑手端必须展示（decision-142）

**个人套餐逾期**（我的服务卡 + 支付占用费 + 扫码仅还电 + 还电成功页）：

- 套餐已结束 · 待还电
- 逾期时间、已逾期天数（不足一天按一天）
- **逾期费用 ¥**（当前应付；系统计费与减免后应付分开展示）
- 主按钮：未结清 → **支付占用费**；已结清或应付 = 0 → **扫码还电**
- 未付清时扫码拦截：「请先支付电池占用费」

**人天池占用**：展示剩余 0、仅可还电、**已从渠道额度扣除 N 人天，你无需支付占用费**。不出现现金应付。

文案用「电池占用费」，不用「罚款」。

## 6. 计费规则

### 6.1 个人套餐

```
逾期天数 = max(1, ceil((还电时刻或当前时刻 − 进入逾期时刻) / 24h))
应付 = 逾期天数 × 日费 x
```

- 只对个人套餐用户计现金。
- **暂不封顶**：应付不以押金或天数为上限。
- 次数耗尽与按天到期用同一套公式，列表「结束原因」区分 **到期 / 次数耗尽**。
- **先付后还**（覆盖 142 还电不拦 / 押金抵占用费）：
  1. 以发起支付或运营改价时刻锁定系统计费；
  2. 当前应付 = 运营改后金额，未改则为系统计费；
  3. 押金保持在押，**不抵占用费**；占用费单独支付（微信等）进运营商子商户；
  4. 应付 > 0 且未支付 → 不可进入还电；
  5. 应付 = 0（减免）或已支付 → 进入还电；已收占用费不退；
  6. 还电成功后退押走原规则。

### 6.2 人天池

```
占用人天 = max(1, ceil((还电时刻或当前时刻 − 进入占用时刻) / 24h))
扣减对象 = 该骑手所属渠道 × 本运营商的额度池可用余额
```

- **不**向骑手收逾期现金。
- 不从骑手「已分配剩余」扣（已经是 0），从 **池可用**扣。
- 消耗明细新增触发动作：**逾期占用**。
- 渠道侧不新开菜单，在额度池余额与消耗明细中可见。

覆盖 decision-049「无预占则不扣池」：仅针对「剩余 0 仍持电」这一段改为扣池。

## 7. 页面（仅运营商）

菜单位置：**订单与服务 → 逾期管理**（一期，紧挨退款管理）。

### 7.1 页内 Tab

| Tab | 说明 |
|-----|------|
| 个人套餐逾期 | 进行中现金占用 |
| 人天池占用 | 进行中池扣减 |
| 已完结 | 已还电或已恢复额度 |
| 逾期设置 | 日费 x |

KPI：进行中人数、个人待收占用费、人天已扣 / 欠人天。

### 7.2 列表字段

**个人套餐逾期**

| 字段 | 枚举 / 空态 |
|------|-------------|
| 用户 | 姓名、脱敏手机、用户 ID |
| 套餐 | SKU 名 + 单号 |
| 结束原因 | 到期 / 次数耗尽 |
| 逾期时间 | 进入逾期的日期时间；副文案「已逾期 N 天」 |
| 逾期费用 | 当前应付 ¥；若已减免，副文案「系统计费 ¥」 |
| 电池 | SN、型号 |
| 支付状态 | 待支付 / 已付清 / 已减免 |
| 操作 | 详情、催还、修改费用、模拟支付（演示）、模拟还电（未结清不可还电） |

**人天池占用**

| 字段 | 枚举 / 空态 |
|------|-------------|
| 骑手 | 姓名、脱敏手机 |
| 渠道 / 团队 | 渠道名、团队名 |
| 占用时间 | 进入占用的日期时间；副文案「已占用 N 天」 |
| 已扣人天 | 从池扣的累计（不足一天按 1） |
| 池可用（扣后） | 可为负，负值标「欠人天」 |
| 电池 | SN、型号 |
| 操作 | 详情、催还 |

空态：当前筛选无进行中逾期。  
错误态：日费保存 ≤ 0 或空，拦「日费须大于 0」。  
权限：与 `orders.view` 同权可看；改日费走 `pricing.edit` `[假设]`。平台 / 渠道登录无此菜单。

### 7.3 详情抽屉

分区固定两块：**用户信息**、**电池信息**。类型徽章必须是「个人套餐逾期」或「人天池占用」之一。

用户信息：ID、姓名、手机、归属运营商、权益来源、套餐/渠道、服务结束或剩余人天、押金方式。  
电池信息：SN、型号、SOC（无 IoT 则 —）、最后换电时间、持电站点（最后一次）、进入逾期/占用时刻。

个人另附：系统计费、当前应付、支付状态、结清门槛（先付后还）、封顶（无）、**修改逾期费用**（金额 + 原因）、**减免日志**。人天另附占用时间与已扣人天，无改价。

### 7.4 减免日志字段

| 字段 | 说明 |
|------|------|
| 时间 | 操作时刻 |
| 操作人 | 运营商员工 |
| 原应付 | 改前金额 |
| 新应付 | 改后金额（可为 0） |
| 原因 | 必填 |

空态：暂无减免记录。错误态：新应付为空、&lt; 0、&gt; 系统计费、原因为空。

### 7.5 资金实收 · 逾期占用费

运营商「我的流水 → 资金实收」增加模块/类型 **电池占用费**。

- 列表可筛「电池占用费」；KPI 单列占用费实收。
- 流水：全额 `amount = net` 进运营商，手续费按通道 `[假设]` 演示为 0。
- **清分明细不出现占用费**；站点合伙人不切分。
- 减免为 0 的单据不产生实收流水。

## 8. 非目标

- 不做押金阶梯罚没、报失工单、远程锁电、自动续购日租。
- 不做平台逾期工作台。
- 不给链接类、设备租赁、激活码另开逾期账（租赁/激活码二期）。
- 不做减免审批流、占用费分润、按日从押金划账。

## 9. 埋点与成功指标

| 事件 | 时机 | 属性 |
|------|------|------|
| `overdue_enter` | 进入进行中 | type=personal\|day_pool, userId, batterySn |
| `overdue_charge` | 个人日费入账 / 人天扣池 | days, amount 或 quota |
| `overdue_pay` | 骑手支付占用费 | amount, overdue_id |
| `overdue_adjust` | 运营商改应付 | from, to, reason, actor |
| `overdue_settle` | 个人占用费结清（支付或减免为 0） | amount, via=pay\|waive |
| `overdue_return` | 还电出列 | type, days, amountOrQuota |
| `overdue_remind` | 运营商点催还 | type, userId |

- 北极星：逾期持电电池数、平均占用天数。
- 健康：个人待支付占用费、渠道欠人天、催还后 48h 还电率、因未付款未还电人数。

## 10. 风险

- 法务：页面与协议写「电池占用费」，不要写「罚款」。暂不封顶须写进协议。
- 客服：不足一天按一天须在骑手端待还电页展示占用费。
- 资金：占用费全额进运营商资金实收，不抽平台 1%、不进清分。先付后还可能推高丢失率，运营须能减免为 0。
