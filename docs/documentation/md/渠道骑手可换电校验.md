# 渠道骑手可换电校验

> **这是什么**：扫码换电前，系统判断渠道骑手当天能不能取电——靠人天预占，还是只能还电。  
> **依据**：[天数池.md](./天数池.md) · [渠道结算模式规则.md](./渠道结算模式规则.md) · 文末决策索引  
> **写法**：[业务文档写作规范](./业务文档写作规范.md)

---

## 业务设定

### 一句话

渠道人天骑手换电前先过权益门：当天预占成功才能取电；池子不够或个人没额度时**禁止换电**；若手里还拿着电池，只允许还电入柜。**不再**推荐买「1 天 / 单次」应急套餐兜底。

### 谁在什么时候触发

骑手 App / 小程序在**扫码换电前**调用权益校验；真正发起换电时还应再验一次。跨网/跨站是否允许，另走运营商换电范围策略，与本文独立。

### 结果怎么理解

| 情况 | 能否换电 | 能否还电 | 用户侧 |
|------|----------|----------|--------|
| 渠道已预占 / 权益有效 | 能 | 能 | 正常换电 |
| 预占失败（池余额不足等）且持电池 | 不能 | 能 | 待还电；联系渠道续配 |
| 个人无额度且持电池 | 不能 | 能 | 待还电 |
| 无权益且未持电池 | 不能 | — | 拦截；个人路径可引导去购个人套餐；渠道路径提示续配 |
| 个人套餐与渠道身份冲突 | 不能 | 视业务 | 提示先处理个人套餐 |

### 已取消

- 自费应急 SKU / 兜底对象：响应不再返回，界面不引导渠道骑手现场购短周期套餐。  
- 「团队额度使用规则」校验：已废止，不再因团队规则拒换。

### 和换电开始的关系

1. 先做权益校验。  
2. 允许换电 → 再调换电开始。  
3. 不允许换电但允许还电且持电池 → 仅还电路径。  
4. 不允许换电且未持电池 → 展示失败原因。

### 验收相关

原型演示：预占失败·待还电、个人无额度·待还电等。见 [acceptance-criteria.md](./acceptance-criteria.md) 与天数池相关条目。

## 实现附录（开发用）

> 业务读者可跳过。

### A. 接口

`POST /api/v1/entitlement/check`  
请求：user_id、cabinet_sn、可选 site_id / request_time（以服务端时间为准）。  
幂等：同用户+自然日可缓存；swap/start 前须再校验。

### B. 响应字段

allowed_swap、allowed_return、entitlement_type（day_pool / personal_pkg / none）、pool_id、seller_operator_id、today_status（reserved / confirmed / failed / pending_return / not_allocated）、fail_reason、gate_reason（个人无额度 / 预占失败 / null）。  
**废弃**：fallback 自费兜底对象。

### C. 错误码

| 码 | 含义 |
|----|------|
| E001 | 未登记渠道且无有效个人套餐 |
| E002 | 预占失败 |
| E003 | 团队规则（已废止） |
| E004 | 个人与渠道身份冲突 |
| E006 | 个人无额度·待还电 |
| E007 | 预占失败·待还电 |

### D. 流程

```
扫码 → entitlement/check
  ├─ allowed_swap → swap/start
  ├─ 仅还电（持电池）
  └─ 拦截 + fail_reason
```
