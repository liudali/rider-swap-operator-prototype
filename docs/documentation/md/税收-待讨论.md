## 业务设定

### 一句话

一期仍是「一家运营商一个收款子商户、支付成功就清分」；本文只讨论未来能不能、以及怎么把一笔套餐费拆给多个真实服务方记账开票——**未拍板前后台不做多收款主体、不合单、不按法人拆 SKU**。

### 动机

套餐全额进运营商营收，易触碰小规模纳税人门槛，进项抵扣受限。希望在有**真实服务或合同**的前提下，把用户支付金额归属到不同服务提供方，各自记账开票。

### 可以怎么拆（讨论框架，非一期实现）

用户付的一笔套餐费，理论上可拆成：

| 服务基础 | 大致覆盖 | 典型归属（待议） |
|----------|----------|------------------|
| 设备 | 换电柜、电池 | 运营商 / 租赁 SPV / 资方 |
| 场地 | 站点租金、物业 | 场地方 / 运营商区域公司 |
| 电费 | 柜机用电、补能 | 能源公司 / 运营商 |
| 平台 | 软件、设备运维 | 平台公司（与现有 1% 技术服务费区分建模） |

原则：拆分必须有业务实质，不能为降税虚构交易。

### 曾探索又撤掉的「多法人合单」

曾经想过：同一品牌下多个法人、骑手一次支付进多个子商户、SKU 拆成「换电服务费 + 电池使用费」、按城市路由区域法人、协议销售方 = 收款方 = 开票方。  
**已撤出产品与原型，不开发。** 若财务定案，再评估走「只记账拆分」还是「多主体收款」。

### 和一期的边界

| 维度 | 一期 | 税收讨论态 |
|------|------|------------|
| 收款 | 运营商单一子商户 | 可能多主体或监管户 |
| 后台 | 收款账户、资金实收 | 无法人拆分 / 合单配置 |
| 骑手购卡 | 单一收银台、单一协议 | 可能复合协议、分项展示 |
| 退款 | 运营商子商户原路退 | 若多主体则可能分子单退 |
| 用户归属运营商 | 仍按卖套餐 / 卖额度的运营商 | 不变 |

### 待财务确认

1. 一期是否只做账务 / 收入确认拆分（钱仍进运营商），还是必须多主体收款？  
2. 四类基础的比例区间与税目映射？  
3. 小规模纳税人阈值与主体边界？  
4. 退款、已提现、冲正时各份额如何回退？  
5. 是否要月 / 年收款额度管控？

### 讨论通过后产品要做什么

- 财务输出《主体拆分表 + 税目映射》  
- 确定路径：记账拆分 / 多主体收款 / 监管冻结清分  
- 更新 PRD、通道与进件；必要时再迭代原型
