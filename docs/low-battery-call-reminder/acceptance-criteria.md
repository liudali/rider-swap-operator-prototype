# 低电外呼提醒方案 · 用户端验收标准

> 对应 PRD：`docs/PRD.md`  
> 对应原型：`prototype/index.html`  
> 验收范围：方案一——微信小程序引导用户把固定低电外呼号码保存到系统通讯录

## 1. 验收前提

- 外呼服务商已确认全平台使用唯一、固定的主叫外显号码；
- 正式号码仅用于低电提醒，不与营销、催缴等业务共用；
- 服务端返回联系人名称、号码、号码版本和配置状态；
- 小程序隐私保护指引已声明“使用你的通讯录（仅写入）”；
- 真机测试至少覆盖 iOS、鸿蒙及一个主流 Android 系统。

## 2. 主流程验收

### AC-01 首次领电成功后主动引导

**Given**

- 用户已登录并首次成功领取电池；
- 当前号码版本没有保存成功记录；
- 当前号码版本没有主动引导记录；
- 提醒号码配置有效，微信接口可用。

**When**

- 领取成功页展示完成。

**Then**

- 自动展示“别错过低电提醒电话”底部弹层；
- 展示联系人名称和完整提醒号码；
- 明确说明“仅写入，不读取”；
- 提供“保存提醒号码”和“暂不保存”；
- 记录 `low_battery_contact_prompt_view`，`entry=first_pickup`；
- 曝光后写入 `promptedNumberVersion=currentNumberVersion`。

### AC-01A 存量持电用户在下一次换电成功时补一次引导

**Given**

- 用户功能上线前已经持电，本设备从未引导过当前号码版本；
- 当前号码版本没有保存成功记录；
- 提醒号码配置有效，微信接口可用。

**When**

- 日常换电成功页展示完成。

**Then**

- 自动展示与 AC-01 相同的底部弹层；
- 记录 `entry=swap_success`；
- 曝光后写入 `promptedNumberVersion=currentNumberVersion`。

**When**

- 用户只是打开首页或小程序，没有领电/换电成功。

**Then**

- 不自动弹出保存引导。

### AC-02 同一号码版本只主动引导一次

**Given**

- 当前设备已展示过 v1 的主动引导；
- 用户曾选择暂不保存或关闭弹层。

**When**

- 用户再次领电成功、再次换电成功或重新进入首页。

**Then**

- 不再自动弹出 v1 保存引导；
- “我的－来电提醒”仍显示“未保存”并允许手动保存；
- 不影响领取、换电和套餐服务。

### AC-03 用户允许通讯录仅写入权限

**Given**

- 用户从引导或设置页点击“保存提醒号码”；
- 通讯录写入权限尚未决定。

**When**

- 用户在微信授权弹窗点击“允许”。

**Then**

- 记录 `low_battery_contact_permission_result=result:allowed`；
- 调用 `wx.addPhoneContact`；
- 用户可选择“新建联系人”或“添加到已有联系人”；
- 小程序不得读取已有联系人列表。

### AC-04 新建联系人并保存成功

**Given**

- 用户已允许权限并选择“新建联系人”。

**When**

- 系统联系人页打开。

**Then**

- 预填姓名“智格-电量过低提醒”；
- 预填服务端当前提醒号码；
- 预填公司“智格换电”；
- 预填备注“低电提醒专用外呼号码”；
- 用户点击系统“完成”后，API 成功回调；
- 本机记录 `savedNumberVersion=currentNumberVersion`；
- 设置页状态显示“已保存”；
- 成功文案包含“实际显示以手机系统为准”；
- 记录 `low_battery_contact_system_result=result:saved,system_mode:unknown` 及当前号码版本。

### AC-05 添加到已有联系人

**Given**

- 用户已允许权限并选择“添加到已有联系人”。

**When**

- 用户未选择已有联系人便点击完成。

**Then**

- 系统页阻止提交并提示“请选择要添加号码的已有联系人”。

**When**

- 用户选择已有联系人并确认完成。

**Then**

- 状态标记为已保存；
- `wx.addPhoneContact` 回调不提供最终的新建/合并结果，埋点统一记录 `system_mode=unknown`；
- 小程序不自行读取或展示真实联系人列表，选择过程由系统完成。

### AC-06 已保存状态允许重新保存

**Given**

- 当前号码版本已有 API 保存成功记录。

**When**

- 用户进入“我的－来电提醒”。

**Then**

- 显示“已保存”；
- 显示“重新保存”按钮；
- 辅助说明用户删除联系人后可再次保存；
- 不宣称系统正在持续校验联系人存在。

## 3. 异常与边界验收

### AC-07 用户拒绝权限

**When**

- 用户在微信授权弹窗点击“拒绝”。

**Then**

- 状态为 `permission_denied`，不写入 `savedNumberVersion`；
- 展示微信小程序设置开启方法；
- 提供“稍后处理”；
- 不连续重新弹出权限申请；
- 不影响领取、换电、续费等核心服务；
- 埋点结果为 `denied`。

### AC-08 用户取消系统联系人页

**When**

- 用户已允许权限，但在系统联系人页点击“取消”。

**Then**

- 状态为 `system_cancelled`；
- 不记录保存成功版本；
- 返回“来电提醒”设置页；
- 提示“未完成保存，可稍后重试”；
- 埋点结果为 `cancelled`。

### AC-08A 系统或 API 保存失败

**Given**

- 用户已进入系统联系人保存流程。

**When**

- `wx.addPhoneContact` 返回非拒绝、非取消的失败结果。

**Then**

- 未保存用户状态变为 `save_failed`；
- 展示“联系人保存失败”和重新保存入口；
- 不写入新的 `savedNumberVersion`；
- 已保存用户重新保存失败时，保留原有效保存版本；
- 号码更新失败时，继续显示“号码已更新”；
- 记录 `low_battery_contact_system_result=result:failed` 和错误码；
- 不影响领取、换电和套餐服务。

### AC-09 微信接口不支持

**Given**

- 当前微信基础库不支持 `wx.addPhoneContact`，或能力检查失败。

**Then**

- 状态为 `unsupported`；
- 展示“当前微信版本暂不支持”；
- 提供复制提醒号码的降级入口；
- 不展示虚假的系统保存成功结果。

### AC-10 提醒号码配置失败

**Given**

- 服务端未返回有效号码或号码版本。

**Then**

- 状态为 `config_error`；
- 不调用 `wx.addPhoneContact`；
- 不使用客户端历史硬编码号码兜底写入；
- 展示“重试加载”；
- 首页不展示可执行的错误保存按钮。

### AC-11 用户未持有电池

**Given**

- 用户当前未持有电池。

**Then**

- 首页展示“暂无在用电池”空态；
- 不展示 SOC 和低电告警；
- 可从“我的－来电提醒”主动保存号码；
- 首次成功领电时再判断是否需要主动引导。

### AC-12 号码版本变化

**Given**

- 本机已保存 v1；
- 服务端下发 v2 及新号码。

**Then**

- 状态显示“号码已更新”；
- 展示新号码，不再把 v1 显示为当前有效号码；
- 提供“更新提醒号码”；
- 明确说明旧联系人需要用户在系统通讯录自行删除；
- 保存成功后 `savedNumberVersion` 更新为 v2；
- 记录 `old_version=v1,new_version=v2`。

### AC-13 更换设备或清除缓存

**Given**

- 用户在新设备登录，或已清除小程序本地缓存。

**Then**

- 不使用账号服务端的旧设备保存标记抑制当前设备引导；
- 当前设备可针对当前号码版本再次引导一次；
- 服务端埋点不得包含设备通讯录内容。

### AC-14 重复联系人

**When**

- 用户点击“重新保存”。

**Then**

- 允许再次进入系统保存流程；
- 文案优先提示可选择“添加到已有联系人”；
- 小程序不通过读取通讯录判断是否重复。

## 4. 来电效果验收

### AC-15 当前号码已保存

**Given**

- `savedNumberVersion=currentNumberVersion`；
- 外呼实际主叫号码与保存号码完全一致。

**When**

- 低电专线呼入。

**Then**

- 系统来电页应优先显示“智格-电量过低提醒”；
- 仍需接受不同系统可能同时显示号码或拦截标签；
- 测试记录手机型号、系统版本、主被叫运营商和实际截图。

### AC-16 未保存或号码已过期

**Then**

- 原型仅显示号码，不虚构联系人名称；
- 产品不得保证未知号码不会被系统拦截；
- 号码过期状态不算“已保存组”数据。

## 5. 页面完整性

| 页面/弹层 | 字段 | 枚举 | 空态 | 错误态 | 权限差异 |
|---|---|---|---|---|---|
| 登录页 | 产品名、登录按钮、协议 | 未登录/登录成功 | 无会话 | 微信授权失败 | 游客需登录后保存 |
| 首次领电成功页 | 电池 SN、领取电量、站点、提醒状态 | 成功/失败，保存状态 | 无号码时隐藏保存卡 | 领电失败不触发引导 | 仅已登录且领电成功 |
| 首页 | 电池 SN、SOC、预计可用、提醒状态 | 正常/偏低/过低 | 未持有电池 | 电池数据加载失败 | 游客需登录 |
| 订单 | 订单号、结果、站点、时间、电池、权益 | 换电/购买/退租 | 当前分类无记录 | 加载失败可重试 | 仅本人订单 |
| 我的 | 用户、服务、提醒名称与状态 | 未保存/已保存/未授权/已更新 | 未登录 | 状态读取失败 | 登录后可操作 |
| 来电提醒设置 | 名称、号码、来源、版本、状态 | §2、§3 全部保存状态 | 未配置号码 | 配置失败/接口不支持 | 游客只看说明 |
| 微信授权弹窗 | 权限用途 | 允许/拒绝 | 不适用 | 授权组件异常 | 已授权可跳过 |
| 系统联系人页 | 姓名、手机、公司、备注 | 新建/合并 | 合并未选联系人 | 取消/保存失败 | 手机系统控制 |
| 来电效果页 | 联系人名、号码、呼叫状态 | 呼入/接通/拒绝/结束 | 无任务不展示 | 拦截/线路失败不在本期 | 终端系统控制 |

## 6. 埋点与数据验收

- [ ] 引导曝光、保存点击、授权结果、系统保存结果、号码更新分别上报；
- [ ] 每个事件均携带 `number_version` 或可关联到对应版本；
- [ ] 主动引导与手动设置入口可通过 `entry` 区分；
- [ ] 保存结果可区分 `saved/cancelled/failed`；
- [ ] 系统保存结果统一记录 `system_mode=unknown`，不虚构新建/合并结果；
- [ ] 不上传联系人列表、已有联系人名称、通讯录数量；
- [ ] 外呼平台回传可与用户及号码版本关联；
- [ ] 可计算已保存组和未保存组的接通率及 30 分钟内换电率。

## 7. 体验与可访问性

- [ ] 主要按钮在 390px 宽移动视口内不截断；
- [ ] 页面支持鼠标和键盘操作，焦点状态可见；
- [ ] 弹窗提供明确主次操作，不依赖点击遮罩完成关键确认；
- [ ] 状态不只依赖颜色，同时展示文字；
- [ ] 用户拒绝、取消和错误后均有可恢复入口；
- [ ] 原型在桌面宽屏和 980px 以下布局均可阅读；
- [ ] 系统联系人模拟页明确标注“正式页面以手机系统为准”。

## 8. 发布判定

以下任一项不满足，判定为阻断上线：

- 外显号码并非固定号码；
- 正式号码承担非低电外呼；
- 用户拒绝权限后被阻断换电；
- 系统取消仍被记录为保存成功；
- 隐私指引未声明通讯录仅写入；
- API 失败时仍写入硬编码历史号码；
- 缺少 iOS、鸿蒙或 Android 真机验证证据。
