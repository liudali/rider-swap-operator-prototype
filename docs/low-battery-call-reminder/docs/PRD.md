# 低电外呼提醒方案 · 用户端 PRD

> 版本：V1.3  
> 日期：2026-09-09  
> 阶段：MVP 验证  
> 方案范围：方案一——通过微信小程序引导用户把固定低电外呼号码保存到系统通讯录  
> 配套原型：`../prototype/index.html`（本地 `http://127.0.0.1:8776/prototype/index.html`）  
> 文档浏览器：`../docs/index.html`  
> 验收标准：`../acceptance-criteria.md`

## 1. 结论

一期采用“小程序引导保存通讯录”方案：本需求上线后，仅在用户**换电成功**时主动弹一次添加引导；取电成功不弹窗。每一个用户只展示一次，号码变更也不再加弹。

我的页来电提醒入口：上线后用户**第一次取电或换电成功**开始计时，展示 **7 个自然日**（含当天），第 8 天起从「我的」隐藏。之后只保留「我的 → 设置 → 来电提醒」。首页提醒卡与我的页共用同一 7 天窗口，避免第三永久入口。

小程序不得静默写入、不得读取用户通讯录，也不得把“调用成功”描述成“已保存”。因为没有通讯录读取权限，产品界面不维护保存状态。

## 2. 背景与目的

### 2.1 用户问题

低电提醒电话使用陌生号码外呼，部分骑手会拒接、漏接或被手机拦截，无法及时知道所持电池电量不足。

### 2.2 业务目标

通过一次保存，让后续低电来电显示联系人名称“**智格-电量过低提醒**”，降低陌生号码识别成本，提高低电提醒电话接通率和提醒后的及时换电率。

### 2.3 当前替代方案

- 用户凭陌生号码和通话内容判断来电用途；
- 用户接听失败后等待再次外呼；
- 客服或运营人员补充通知。

### 2.4 为什么现在

- 已确认低电外呼使用全平台唯一固定号码；
- 微信小程序已有通讯录仅写入能力；
- 相比运营商来显认证，本方案依赖少、验证周期短。

## 3. 产品判断

### 3.1 价值量化

- 新体验：来电直接显示低电提醒名称，用户在接听前即可识别用途。
- 旧体验：陌生号码来电，用户需要猜测或直接拒接。
- 替换成本：一次点击、一次微信授权、一次系统联系人确认。
- 核心判断：在固定号码稳定的前提下，长期收益大于一次性操作成本。

### 3.2 支持、反对与失效条件

- ✅ 支持理由：全平台固定号码可被一个联系人长期匹配，方案链路短。
- ❌ 反对理由：授权与系统确认存在流失；用户可能删除联系人；部分系统仍可能拦截来电。
- ⚠️ 失效条件：
  1. 外显号码发生轮换；
  2. 该号码同时承担营销或其他业务外呼，联系人名称与真实来意不一致；
  3. 外呼服务商不能保证主叫外显号码与保存号码一致。

## 4. 前置假设与依赖

| 项目 | 当前口径 | 产品约束 |
|---|---|---|
| 主叫号码模式 | 全平台唯一固定号码 | 外呼服务商不得按呼叫动态换号 |
| 号码权属 | 外呼服务商分配 | 服务商需提供外显号码稳定性承诺 |

| 小程序能力 | `wx.addPhoneContact` | 需 `scope.addPhoneContact`，由用户主动触发 |
| 号码配置 | 服务端下发 | 不在客户端硬编码；携带 `numberVersion` |

`[待确认]` 正式外呼号码、服务商换号通知周期、旧号码与新号码并行期。

## 5. 目标用户与用户故事

### 5.1 目标用户

已登录智格换电小程序、且本设备会发生低电外呼的骑手：个人套餐与渠道骑手一视同仁，不以运营商或结算模式区分。

### 5.2 用户故事

作为持有电池的骑手，我希望把低电提醒专线保存为容易识别的联系人，以便电量不足时能及时识别并接听智格来电。

作为曾拒绝授权或取消保存的骑手，我希望在 7 天窗口内从「我的」再次添加，窗口结束后仍能从「设置」进入，而不是被系统反复强制弹窗。

作为号码已变更的骑手，我希望明确知道旧号码已失效，并能把新号码更新到通讯录。

## 6. 范围

### 6.1 本期范围

1. 换电成功后的一次主动保存引导（每用户 1 次；取电成功不弹）；
2. 「我的」来电提醒入口：首次取电/换电成功后展示 7 个自然日，可直接添加到通讯录；
3. 「我的 → 设置」常驻入口，7 天后为唯一手动入口；
4. 微信通讯录写入授权；
5. 系统“新建联系人 / 添加到已有联系人”与联系人确认页；
6. 一次性操作反馈：系统页完成、取消、权限拒绝、写入失败、接口不支持、配置异常；
7. 号码版本变化后在设置页展示新号码（不再因此加一次主动弹窗）；
8. 原型内模拟低电来电显示效果（演示假设，不代表产品能判断是否已添加）；
9. 埋点事件。

### 6.2 Non-goals

- 不读取、搜索或校验用户现有通讯录；
- 不在产品界面展示“已保存 / 未保存 / 未完成保存 / 号码已更新（作为保存状态）”；
- 不依据本地成功回调抑制添加入口；
- 不静默新增或修改联系人；
- 不实现运营商/手机厂商企业来显认证；
- 不实现真实低电检测、真实电话外呼；
- 不实现短信、微信订阅消息等兜底通道；
- 不支持多个轮换号码或按运营商保存不同号码；
- 不把保存通讯录作为换电或使用服务的强制条件。

## 7. 信息架构

用户端沿用智格换电小程序三 Tab：

| Tab | 本需求关联能力 |
|---|---|
| 首页 | 持有电池及低电状态；7 天窗口内展示提醒保障卡 |
| 订单 | 仅用于保持现有导航完整，本需求不新增业务 |
| 我的 | 7 天窗口内展示「来电提醒」并可直接添加；始终提供「设置」 |

本需求新增页面/弹层：

1. 领取/换电成功页（取电成功可保留手动添加按钮，不算主动弹窗）；
2. 保存低电提醒号码底部弹层（仅换电成功触发）；
3. 微信通讯录写入授权弹窗；
4. 新建/合并联系人选择；
5. 系统联系人确认页模拟；
6. 小程序设置页（来电提醒常驻行）；
7. 来电提醒详情页；
8. 低电来电效果模拟页。

## 8. 核心流程

### 8.0 引导策略（时机 / 人群 / 是否重复）

结论：**主动弹窗只在本需求上线后的「换电成功」出现，每一个用户只展示一次。取电成功不弹。号码变更不加弹。我的页入口从首次取电或换电成功起展示 7 个自然日，之后只留在设置里。产品不判断用户是否已经写入通讯录。**

#### 8.0.1 何时弹

| 触发点 | 是否主动弹窗 | 原因 |
|---|---|---|
| 日常换电成功（柜门关闭、结果页出现） | 是，仅当该用户从未展示过本次弹窗 | 换电是高频刚需节点，存量持电用户 1–2 天内可覆盖 `[假设]` |
| 首次领取电池成功 | 否 | 用户要求弹窗只绑换电成功；结果页可保留手动「添加到通讯录」 |
| 进入首页 / 打开小程序 | 否 | 与换电任务无关，容易被当成骚扰 |
| 电量已偏低或外呼正在拨打 | 否 | 与“去换电”抢注意力，且来不及改变当次识别 |
| 登录、实名、购套餐 | 否 | 当时还没有持电，价值说不清 |
| 扫码开柜过程中 | 否 | 打断柜机操作 |

弹层**真正展示**时写入 `swapPromptShown=true`（账号维度，服务端）。配置失败、接口不支持、未登录不写次数，避免占掉唯一一次。结果页刷新或杀进程后，以服务端标记为准，不连环弹出。

自然日按 `Asia/Shanghai` 日历日计算：首次取电/换电当天 = 第 1 天；`calendarDaysBetween < 7` 为展示窗口。例：9 月 9 日发生 → 9/9–9/15 显示，9/16 起隐藏。

#### 8.0.2 向谁弹

必须同时满足：

1. 已登录；
2. 本次**换电成功**（取电成功、领电/换电失败都不弹）；
3. 服务端已下发有效提醒号码和 `numberVersion`；
4. 当前微信基础库支持 `wx.addPhoneContact`；
5. 该用户 `swapPromptShown !== true`。

不弹窗的对象：

| 用户 | 处理 |
|---|---|
| 未登录游客 | 不弹；添加入口先登录 |
| 取电成功 | 不弹；可手动添加；开始 7 天「我的」入口 |
| 领电/换电失败 | 不弹；不开始 7 天窗口 |
| 本用户已看过换电弹窗（含暂不添加、关闭、拒绝） | 不弹 |
| 接口不支持 | 不走授权弹窗，仅提供复制号码；**不占** `swapPromptShown` |
| 号码配置失败 | 不弹，避免写入错误号码；**不占** `swapPromptShown` |

个人套餐、人天池、链接类、白名单、激活码骑手规则相同。冻结中但仍持有电池的用户，换电成功时仍按上表判断。

上线前从未取电/换电：我的页不展示来电提醒卡片；「设置」仍可进入来电提醒。

#### 8.0.3 要不要重复提醒

| 情形 | 主动弹窗 | 说明 |
|---|---|---|
| 同一用户，点了暂不添加/关闭 | 不再弹 | 已表达“现在不要”；次数已记 |
| 同一用户，拒绝通讯录权限 | 不再弹 | 7 天内我的页、之后设置页保留“去开启” |
| 同一用户，系统联系人页取消或写入失败 | 不再自动弹 | 结果页可继续点添加；之后走手动入口 |
| 用户再次领电或换电 | 不再弹 | 防止每次换电都打扰 |
| 每天/每次打开小程序 | 不弹 | 禁止日历式重复营销 |
| 漏接低电来电之后 | MVP 不弹 | 没有可靠信号证明“因陌生号码未接” |
| 号码版本变更（v1→v2） | 不再加弹 | 设置页展示新号码，用户手动添加；不声称旧联系人“已过期保存” |
| 换设备 | 不再弹 | `swapPromptShown` 按 **userId 服务端**，换机不重复 |
| 清除小程序缓存 | 不因缓存丢失再弹 | 以服务端标记为准 |
| 我的页「添加到通讯录」（7 天内） | 窗口内手动入口 | 不算重复提醒；埋点 `entry=mine` |
| 设置页「来电提醒」 | 常驻手动入口 | 埋点 `entry=settings` |

一句话给开发：**主动弹窗上限 = 每个用户终身 1 次，仅换电成功节点；配置失败/不支持不计数。**

#### 8.0.4 我的页 7 天入口

| 规则 | 口径 |
|---|---|
| 计时起点 | 本需求上线后，该用户第一次**取电成功或换电成功**的日历日 |
| 展示时长 | 7 个自然日（当天为第 1 天） |
| 窗口内 | 「我的」展示来电提醒卡片（含直接添加）；「设置」也可进 |
| 第 8 天起 | 「我的」隐藏该卡片；首页提醒保障卡同步隐藏 |
| 永久入口 | 「我的 → 设置 → 来电提醒」 |
| 上线后从未取电/换电 | 「我的」不展示卡片；设置可进 |

`[待确认]` 生产是否按账号服务端记录 `firstPowerEventAt` / `swapPromptShown`（建议是，避免换机重复弹、清缓存重置窗口）。

### 8.1 换电成功后的主动引导

1. 用户日常换电成功；
2. 系统读取该用户 `swapPromptShown` 与配置，确认 §8.0.2 全部满足；
3. 展示底部弹层，说明“添加后，低电电话将显示联系人名称”；
4. 用户点击“添加到通讯录”；
5. 微信申请“使用你的通讯录（仅写入）”权限；
6. 用户允许后，小程序调用 `wx.addPhoneContact`；
7. 系统让用户选择新建联系人或添加到已有联系人；
8. 系统联系人页预填联系人信息，用户确认保存；
9. 展示一次性完成反馈。不写入“已保存”产品状态。

埋点 `entry`：换电弹窗/结果页为 `swap_success`，取电结果页手动添加为 `first_pickup`，我的页为 `mine`，设置/详情页为 `settings`。弹窗曝光带 `user_once=1`。

### 8.2 用户稍后处理

1. 用户点击“暂不添加”或关闭弹层；
2. 该用户不再自动弹出；
3. 7 天窗口内「我的－来电提醒」继续展示「添加到通讯录」，不展示“未保存”；
4. 窗口结束后从「设置－来电提醒」再次添加。

### 8.3 权限拒绝

1. 用户拒绝通讯录写入权限；
2. 展示原因和“去设置”引导；
3. 不影响换电服务；
4. 后续仅在用户手动点击时重新申请，不主动连环弹窗。

### 8.4 系统页取消

用户允许微信权限，但在系统联系人页取消：记录事件 `cancelled`，Toast 提示可稍后再次添加。页面回到可添加，不留下“未完成保存”状态。

### 8.5 系统或 API 保存失败

1. `wx.addPhoneContact` 返回非拒绝、非取消的失败；
2. 展示一次性错误弹层，提供“重新添加”；
3. 关闭后页面仍是可添加，不留下“保存失败”状态；
4. 不影响换电服务。

### 8.6 号码变更

1. 服务端下发新的 `numberVersion`；
2. **不再**因此增加一次主动弹窗；
3. 用户进入设置/来电提醒详情时展示新号码，可提示“号码已更换，建议重新添加”；
4. 旧联系人由用户在系统通讯录自行删除，小程序不代删、不核对。

## 9. 状态模型

小程序**没有通讯录读取权限**，不能判断联系人是否存在。因此产品状态只描述“当前能不能添加”，不描述“有没有保存成功”。

### 9.1 能力状态枚举

| 状态值 | 用户文案 | 是否展示为页面状态 | 说明 |
|---|---|---|---|
| `ready` | 可添加 | 否，只作默认能力 | 可点击「添加到通讯录」 |
| `prompting` | 添加中 | 否，仅流程中 | 授权或系统联系人页进行中 |
| `permission_denied` | 未授权写入 | 是 | 用户拒绝仅写入权限，可去开启 |
| `unsupported` | 当前微信版本暂不支持 | 是 | 降级为复制号码 |
| `config_error` | 提醒号码加载失败 | 是 | 无可用号码，禁止写入 |

禁止作为产品状态：`未保存`、`已保存`、`未完成保存`、`保存失败`、`号码已更新（作为保存结果）`。

系统页完成、取消、失败只作为**一次性反馈**（弹层 / Toast / 埋点 `lastWriteResult`），关闭后回到 `ready`。

### 9.2 本地状态

| 字段 | 类型 | 示例 | 说明 |
|---|---|---|---|
| `swapPromptShown` | boolean | `false` | 该用户是否已展示过换电弹窗。建议服务端按 userId 存储 |
| `firstPowerEventAt` | datetime/null | `2026-09-09T14:28:00+08:00` | 上线后首次取电或换电成功时间，用于 7 天窗口 |
| `permission` | enum | `prompt/granted/denied` | 微信写入权限 |
| `lastWriteResult` | enum/null | `api_success/cancelled/failed` | 最近一次系统页结果，仅排查和埋点，不驱动页面状态 |

禁止再用 `promptedNumberVersion` 控制弹窗次数。账号服务端不得用“已保存”标记抑制引导。换设备以 `swapPromptShown` 为准，不重复弹。

## 10. 页面规格

### 10.1 领取 / 换电成功页

| 项 | 规格 |
|---|---|
| 字段 | 领取/换电结果、电池编号、当前电量 |
| 枚举 | 领取成功 / 换电成功 / 失败 |
| 空态 | 无低电提醒号码配置时隐藏添加入口 |
| 错误态 | 失败时不弹添加引导，不开始 7 天窗口 |
| 权限差异 | 仅已登录且成功用户；未登录用户不可进入 |
| 主操作 | 添加到通讯录（手动，取电/换电结果页均可保留） |
| 主动弹窗 | 仅换电成功且 `swapPromptShown=false` |
| 次操作 | 暂不添加 / 返回首页 |

### 10.2 首页低电状态卡

| 项 | 规格 |
|---|---|
| 字段 | 电池编号、SOC、电量状态、预计可用、提醒保障状态 |
| 枚举 | 电量正常 / 电量偏低 / 电量过低 |
| 空态 | 未持有电池：展示“暂无在用电池”，不展示低电操作 |
| 错误态 | 电池数据加载失败：展示重试，不推断低电 |
| 权限差异 | 仅持有电池用户可见电池卡；游客需登录 |
| 操作 | 7 天窗口内：查看来电提醒、模拟低电来电（仅原型）；窗口外不展示提醒卡 |

### 10.3 登录页

| 项 | 规格 |
|---|---|
| 字段 | 产品名、登录按钮、协议勾选说明 |
| 枚举 | 未登录 / 登录成功 |

## 11. 交互与文案

### 11.1 首次引导

标题：`别错过低电提醒电话`

正文：`保存“智格-电量过低提醒”后，电量不足来电会显示名称，更容易识别。`

辅助说明：`微信仅申请通讯录写入权限，不会读取你的联系人。`

按钮：`添加到通讯录` / `暂不添加`

### 11.2 成功反馈

`已提交到系统通讯录。请在手机里确认联系人。小程序不能读取通讯录，因此不会显示“已保存”；之后来电是否显示名称，以手机系统为准。`

### 11.3 号码更新

`低电提醒号码已更换，建议把新号码重新添加到通讯录。旧联系人请在手机通讯录中自行删除。`

## 12. 微信能力映射

调用参数：

```js
wx.addPhoneContact({
  firstName: '智格-电量过低提醒',
  mobilePhoneNumber: reminderNumber,
  organization: '智格换电',
  remark: '低电提醒专用外呼号码'
})
```

实现要求：

1. 调用前检查基础库兼容性；
2. 在小程序隐私保护指引声明“使用你的通讯录（仅写入）”；
3. 必须由用户点击触发；
4. `success` 时只做一次性反馈和埋点，**不得**写入“已保存”产品状态；
5. `fail` 区分拒绝、取消、不支持和其他错误；
6. 不调用通讯录读取接口判断联系人是否存在。
7. `wx.addPhoneContact` 回调不提供用户最终选择“新建/合并”的结果，生产埋点统一记录 `system_mode=unknown`，不得虚构 `new/merge`。

## 13. 数据埋点

| 事件名 | 触发时机 | 关键属性 |
|---|---|---|
| `low_battery_contact_prompt_view` | 换电成功主动引导曝光 | `number_version`、`entry=swap_success`、`user_once=1` |
| `low_battery_contact_save_click` | 点击添加 | `entry=first_pickup/swap_success/mine/settings`、`capability`、`number_version` |
| `low_battery_contact_permission_result` | 微信授权结束 | `result=allowed/denied`、`number_version` |
| `low_battery_contact_system_result` | 系统联系人页返回 | `result=api_success/cancelled/failed`、`system_mode=unknown`、`number_version`、失败时 `error_code` |
| `low_battery_contact_settings_view` | 进入设置页 | `capability`、`number_version` |
| `low_battery_contact_update_view` | 号码变化提示曝光 | `old_version`、`new_version` |

## 14. 成功指标

- 北极星指标：低电提醒电话接通率。
- 驱动指标：
  - 首次引导后完成系统页确认的比例（事件口径，不是“已保存用户数”）；
  - 手动入口再次添加点击率；
  - 提醒后 30 分钟内换电率。
- 健康指标：
  - 权限拒绝率；
  - 弹层关闭率；
  - 与“误导来电名称、重复联系人、骚扰”相关投诉率。

`[假设]` MVP 目标：

- 首次引导后系统页确认率 ≥ 35%；
- 不按“已保存组 / 未保存组”切接通率（产品无法判定）；接通率看全量持电用户；
- 相关投诉率不高于提醒用户数的 0.5%。

## 15. 异常与边界

1. **重复添加**：允许再次调用；文案提示可选择“添加到已有联系人”。
2. **用户删除联系人**：小程序无法感知，添加入口始终保留。
3. **更换手机或清除缓存**：弹窗按账号 `swapPromptShown`，不因换机或清缓存再弹；7 天窗口按 `firstPowerEventAt` 账号记录。
4. **双卡手机**：联系人匹配由系统处理，与拨入 SIM 无关；仍需真机验证。
5. **号码格式**：服务端同时下发 E.164 标准值和本地展示值；真机验证 `+86` 与本地号码匹配。
6. **用户拒绝授权**：不阻断服务，不在当前链路连续追问。
7. **系统页取消**：不标记成功。
8. **接口不支持**：展示手动复制号码，不诱导用户升级之外的强制操作。
9. **号码变化**：新旧号码不得复用同一版本；旧号码删除由用户完成。
10. **同号多用途**：若专线承担非低电外呼，本方案暂停上线。

## 16. 合规与隐私

- 遵循最小必要：仅申请通讯录写入，不读取通讯录；
- 权限前置说明必须明确目的、数据范围和是否影响核心服务；
- 用户拒绝后仍可正常领取、换电和使用套餐；
- 小程序隐私保护指引、隐私政策和实际接口调用保持一致；
- 仅记录授权与保存结果，不记录用户通讯录数据；
- 正式上线前由法务复核《个人信息保护法》告知文本及外呼同意基础。

## 17. 发布门槛

以下条件全部满足方可上线：

1. 服务商书面确认主叫外显号码固定且与配置一致；
2. 正式号码仅用于低电提醒；
3. iOS、鸿蒙及主流 Android 至少各完成一次新增、合并、取消、拒绝测试；
4. 隐私保护指引审核通过；
5. 埋点可区分主动引导、手动保存与号码更新；
6. 客服已具备号码变化、重复联系人和权限拒绝处理话术。
