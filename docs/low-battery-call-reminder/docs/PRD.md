# 低电外呼提醒方案 · 用户端 PRD

> 版本：V1.0  
> 日期：2026-09-09  
> 阶段：MVP 验证  
> 方案范围：方案一——通过微信小程序引导用户把固定低电外呼号码保存到系统通讯录  
> 配套原型：`../prototype/index.html`（本地 `http://127.0.0.1:8776/prototype/index.html`）  
> 文档浏览器：`../docs/index.html`  
> 验收标准：`../acceptance-criteria.md`

## 1. 结论

一期采用“小程序引导保存通讯录”方案：用户首次领取电池成功后，小程序解释保存价值，并调用微信 `wx.addPhoneContact`。用户授权后，在手机系统联系人页面自行选择“新建联系人”或“添加到已有联系人”并确认。

小程序不得静默写入、不得读取用户通讯录，也不得把“调用成功”描述成持续可验证的通讯录状态。

## 2. 背景与目的

### 2.1 用户问题

低电提醒电话使用陌生号码外呼，部分骑手会拒接、漏接或被手机拦截，无法及时知道所持电池电量不足。

### 2.2 业务目标

通过一次保存，让后续低电来电显示联系人名称“**智格-电量过低提醒**”，降低陌生号码识别成本，提高低电提醒电话接通率和提醒后的及时换电率。

### 2.3 当前替代方案

- 用户凭陌生号码和通话内容判断来电用途；
- 用户接听失败后等待再次外呼；
- 客服或运营人员补充通知。

### 2.4 为什么现在

- 已确认低电外呼使用全平台唯一固定号码；
- 微信小程序已有通讯录仅写入能力；
- 相比运营商来显认证，本方案依赖少、验证周期短。

## 3. 产品判断

### 3.1 价值量化

- 新体验：来电直接显示低电提醒名称，用户在接听前即可识别用途。
- 旧体验：陌生号码来电，用户需要猜测或直接拒接。
- 替换成本：一次点击、一次微信授权、一次系统联系人确认。
- 核心判断：在固定号码稳定的前提下，长期收益大于一次性操作成本。

### 3.2 支持、反对与失效条件

- ✅ 支持理由：全平台固定号码可被一个联系人长期匹配，方案链路短。
- ❌ 反对理由：授权与系统确认存在流失；用户可能删除联系人；部分系统仍可能拦截来电。
- ⚠️ 失效条件：
  1. 外显号码发生轮换；
  2. 该号码同时承担营销或其他业务外呼，联系人名称与真实来意不一致；
  3. 外呼服务商不能保证主叫外显号码与保存号码一致。

## 4. 前置假设与依赖

| 项目 | 当前口径 | 产品约束 |
|---|---|---|
| 主叫号码模式 | 全平台唯一固定号码 | 外呼服务商不得按呼叫动态换号 |
| 号码权属 | 外呼服务商分配 | 服务商需提供外显号码稳定性承诺 |
| 联系人名称 | 智格-电量过低提醒 | 仅用于低电提醒专线 |
| 小程序能力 | `wx.addPhoneContact` | 需 `scope.addPhoneContact`，由用户主动触发 |
| 号码配置 | 服务端下发 | 不在客户端硬编码；携带 `numberVersion` |

`[待确认]` 正式外呼号码、服务商换号通知周期、旧号码与新号码并行期。

## 5. 目标用户与用户故事

### 5.1 目标用户

已登录智格换电小程序、且本设备会发生低电外呼的骑手：个人套餐与渠道骑手一视同仁，不以运营商或结算模式区分。

### 5.2 用户故事

作为持有电池的骑手，我希望把低电提醒专线保存为容易识别的联系人，以便电量不足时能及时识别并接听智格来电。

作为曾拒绝授权或取消保存的骑手，我希望之后能从“我的”重新发起保存，而不是被系统反复强制弹窗。

作为号码已变更的骑手，我希望明确知道旧号码已失效，并能把新号码更新到通讯录。

## 6. 范围

### 6.1 本期范围

1. 领取/换电成功后的一次主动保存引导（含存量持电用户的下一次换电）；
2. “我的－来电提醒”常驻入口；
3. 微信通讯录写入授权；
4. 系统“新建联系人 / 添加到已有联系人”与联系人确认页；
5. 保存成功、主动取消、权限拒绝、系统/API 保存失败、接口不支持、配置异常；
6. 已保存状态下重新保存；
7. 号码版本变化后的更新提醒；
8. 原型内模拟低电来电显示效果和埋点事件。

### 6.2 Non-goals

- 不读取、搜索或校验用户现有通讯录；
- 不静默新增或修改联系人；
- 不实现运营商/手机厂商企业来显认证；
- 不实现真实低电检测、真实电话外呼；
- 不实现短信、微信订阅消息等兜底通道；
- 不支持多个轮换号码或按运营商保存不同号码；
- 不把保存通讯录作为换电或使用服务的强制条件。

## 8. 核心流程

### 8.0 引导策略（时机 / 人群 / 是否重复）

结论：**只在领电或换电成功之后弹一次；同设备、同号码版本不重复；未保存只留手动入口。**

#### 8.0.1 何时弹

| 触发点 | 是否主动弹窗 | 原因 |
|---|---|---|
| 首次领取电池成功（柜门关闭、结果页出现） | 是，满足条件则弹 | 用户刚开始持电，低电来电即将发生，替换成本最低 |
| 日常换电成功 | 是，仅当本设备还从未引导过当前号码版本 | 覆盖功能上线前已经持电的存量骑手；骑手高频换电，1–2 天内可覆盖 `[假设]` |
| 进入首页 / 打开小程序 | 否 | 与换电任务无关，容易被当成骚扰 |
| 电量已偏低或外呼正在拨打 | 否 | 与“去换电”抢注意力，且来不及改变当次识别 |
| 登录、实名、购套餐 | 否 | 当时还没有持电，价值说不清 |
| 扫码开柜过程中 | 否 | 打断柜机操作 |

弹窗出现即写入 `promptedNumberVersion = currentNumberVersion`，避免结果页刷新或杀进程后连环弹出。

#### 8.0.2 向谁弹

必须同时满足：

1. 已登录；
2. 本次领电或换电成功（失败不弹）；
3. 服务端已下发有效提醒号码和 `numberVersion`；
4. 当前微信基础库支持 `wx.addPhoneContact`；
5. 本设备 `savedNumberVersion !== currentNumberVersion`；
6. 本设备 `promptedNumberVersion !== currentNumberVersion`。

不弹窗的对象：

| 用户 | 处理 |
|---|---|
| 未登录游客 | 不弹；保存入口先登录 |
| 领电/换电失败 | 不弹 |
| 未持电且本次未领电成功 | 不弹，因其不会接到低电外呼 |
| 本设备已保存当前号码 | 不弹 |
| 本设备已看过当前号码的主动引导（含暂不保存、关闭、拒绝） | 不弹 |
| 接口不支持 | 不走授权弹窗，仅在设置页提供复制号码 |
| 号码配置失败 | 不弹，避免写入错误号码 |

个人套餐、人天池、链接类、白名单、激活码骑手规则相同。冻结中但仍持有电池的用户，换电成功时仍按上表判断。

#### 8.0.3 要不要重复提醒

| 情形 | 主动弹窗 | 说明 |
|---|---|---|
| 同一设备、同一号码版本，用户点了暂不保存/关闭 | 不再弹 | 已表达“现在不要” |
| 同一设备，用户拒绝通讯录权限 | 不再弹 | 只保留设置页“去开启” |
| 同一设备，系统联系人页取消或保存失败 | 不再自动弹 | 结果页可继续点保存；之后只走手动入口 |
| 用户再次领电或换电 | 不再弹 | 防止每次换电都打扰 |
| 每天/每次打开小程序 | 不弹 | 禁止日历式重复营销 |
| 漏接低电来电之后 | MVP 不弹 | 没有可靠信号证明“因陌生号码未接”；转化不足时再评估 1 次补救 |
| 号码版本变更（v1→v2） | 再弹 1 次 | 旧联系人已失效，属于新任务 |
| 换设备或清除小程序缓存 | 再弹 1 次 | 本地状态丢失，无法确认通讯录仍在 |
| 首页/我的「未保存」状态点 | 常驻，非弹窗 | 不算重复提醒 |

一句话给开发：**主动弹窗上限 = 每台设备每个 `numberVersion` 最多 1 次；号码变更才加 1 次。**

### 8.1 领电或换电成功后的主动引导

1. 用户领取电池成功，或日常换电成功；
2. 系统读取本机小程序缓存，确认 §8.0.2 全部满足；
3. 展示底部弹层，说明“保存后，低电电话将显示联系人名称”；
4. 用户点击“保存提醒号码”；
5. 微信申请“使用你的通讯录（仅写入）”权限；
6. 用户允许后，小程序调用 `wx.addPhoneContact`；
7. 系统让用户选择新建联系人或添加到已有联系人；
8. 系统联系人页预填联系人信息，用户确认保存；
9. 小程序记录本机状态和埋点，展示成功反馈。

埋点 `entry`：首次领电为 `first_pickup`，日常换电为 `swap_success`。

### 8.2 用户稍后处理

1. 用户点击“暂不保存”或关闭弹层；
2. 本号码版本不再自动弹出；
3. “我的－来电提醒”持续显示“未保存”；
4. 用户可随时手动进入并再次发起保存。

### 8.3 权限拒绝

1. 用户拒绝通讯录写入权限；
2. 展示原因和“去设置”引导；
3. 不标记为已保存，不影响换电服务；
4. 后续仅在用户手动点击时重新申请，不主动连环弹窗。

### 8.4 系统页取消

用户允许微信权限，但在系统联系人页取消：记录 `system_cancelled`，返回设置页并提示“未完成保存，可稍后重试”。

### 8.5 系统或 API 保存失败

1. `wx.addPhoneContact` 返回非拒绝、非取消的失败；
2. 状态变为 `save_failed`，展示可恢复错误提示；
3. 不写入新的 `savedNumberVersion`；
4. 如果本机已有当前版本的成功记录，保留原“已保存”状态，仅提示本次重新保存失败；
5. 用户可稍后处理或重新发起保存，不影响换电服务。

### 8.6 号码变更

1. 服务端下发的新 `numberVersion` 与本机 `savedNumberVersion` 不一致；
2. 状态变为“号码已更新”；
3. 首页和“我的”展示一次非阻断提示；
4. 用户重新保存新号码；
5. 提示用户可在系统通讯录中删除旧号码，小程序不代删。

## 9. 状态模型

### 9.1 保存状态枚举

| 状态值 | 用户文案 | 说明 |
|---|---|---|
| `not_saved` | 未保存 | 尚无本版本成功记录 |
| `prompting` | 保存中 | 正在授权或系统确认 |
| `permission_denied` | 未授权通讯录 | 用户拒绝仅写入权限 |
| `system_cancelled` | 未完成保存 | 用户从系统页取消 |
| `save_failed` | 保存失败 | 系统或 API 未完成联系人写入 |
| `saved` | 已保存 | 本版本收到 API 成功回调；不代表可持续校验 |
| `outdated` | 号码已更新 | 已保存版本落后于当前版本 |
| `unsupported` | 当前微信版本暂不支持 | API 或基础库不可用 |
| `config_error` | 提醒号码加载失败 | 无可用号码配置 |

### 9.2 本地状态

| 字段 | 类型 | 示例 | 说明 |
|---|---|---|---|
| `promptedNumberVersion` | string/null | `v1` | 当前设备已主动引导的版本 |
| `savedNumberVersion` | string/null | `v1` | 当前设备收到保存成功回调的版本 |
| `saveStatus` | enum | `saved` | 最近一次操作结果 |
| `lastActionAt` | datetime/null | `2026-09-09T14:00:00+08:00` | 用于问题排查 |

状态保存在当前设备的小程序本地缓存。账号服务端只接收埋点，不使用跨设备“已保存”标记抑制新设备引导。

### 11.1 首次引导

### 11.2 成功反馈

`提醒号码已保存。以后低电来电将优先显示“智格-电量过低提醒”；实际显示以手机系统为准。`

`低电提醒号码已更新，请保存新号码。旧联系人需在手机通讯录中自行删除。`

## 12. 微信能力映射

调用参数：

```js
wx.addPhoneContact({
  firstName: '智格-电量过低提醒',
  mobilePhoneNumber: reminderNumber,
  organization: '智格换电',
  remark: '低电提醒专用外呼号码'
})
```

实现要求：

1. 调用前检查基础库兼容性；
2. 在小程序隐私保护指引声明“使用你的通讯录（仅写入）”；
3. 必须由用户点击触发；
4. `success` 时保存本机号码版本；
5. `fail` 区分拒绝、取消、不支持和其他错误；
6. 不调用通讯录读取接口判断联系人是否存在。
7. `wx.addPhoneContact` 回调不提供用户最终选择“新建/合并”的结果，生产埋点统一记录 `system_mode=unknown`，不得虚构 `new/merge`。

## 14. 成功指标

- 北极星指标：低电提醒电话接通率。
- 驱动指标：
  - 首次引导保存成功率；
  - 手动入口补保存率；
  - 提醒后 30 分钟内换电率。
- 健康指标：
  - 权限拒绝率；
  - 弹层关闭率；
  - 与“误导来电名称、重复联系人、骚扰”相关投诉率。

`[假设]` MVP 目标：

- 首次引导保存成功率 ≥ 35%；
- 已保存组低电电话接通率相对未保存组提升 ≥ 15%；
- 相关投诉率不高于提醒用户数的 0.5%。

## 15. 异常与边界

1. **重复保存**：允许重新调用；提醒用户选择“添加到已有联系人”，避免重复联系人。
2. **用户删除联系人**：小程序无法感知，设置页始终保留“重新保存”。
3. **更换手机或清除缓存**：视为新设备，可再次主动引导一次。
4. **双卡手机**：联系人匹配由系统处理，与拨入 SIM 无关；仍需真机验证。
5. **号码格式**：服务端同时下发 E.164 标准值和本地展示值；真机验证 `+86` 与本地号码匹配。
6. **用户拒绝授权**：不阻断服务，不在当前链路连续追问。
7. **系统页取消**：不标记成功。
8. **接口不支持**：展示手动复制号码，不诱导用户升级之外的强制操作。
9. **号码变化**：新旧号码不得复用同一版本；旧号码删除由用户完成。
10. **同号多用途**：若专线承担非低电外呼，本方案暂停上线。

## 16. 合规与隐私

- 遵循最小必要：仅申请通讯录写入，不读取通讯录；
- 权限前置说明必须明确目的、数据范围和是否影响核心服务；
- 用户拒绝后仍可正常领取、换电和使用套餐；
- 小程序隐私保护指引、隐私政策和实际接口调用保持一致；
- 仅记录授权与保存结果，不记录用户通讯录数据；
- 正式上线前由法务复核《个人信息保护法》告知文本及外呼同意基础。

## 17. 发布门槛

以下条件全部满足方可上线：

1. 服务商书面确认主叫外显号码固定且与配置一致；
2. 正式号码仅用于低电提醒；
3. iOS、鸿蒙及主流 Android 至少各完成一次新增、合并、取消、拒绝测试；
4. 隐私保护指引审核通过；
5. 埋点可区分主动引导、手动保存与号码更新；
6. 客服已具备号码变化、重复联系人和权限拒绝处理话术。
