# 决策卡片 #004

- **日期**：2026-09-09 | **阶段**：MVP

## 决策问题

没有通讯录读取权限，要不要在产品里维护“已保存 / 未保存”状态？

## 调用的大师视角

- **唐·诺曼 · 认知匹配**：状态必须对应用户能验证的事实。读不了通讯录，却显示“已保存”，是错误心智模型。
- **乔布斯 · 极致减法**：删掉无法核实的状态，入口永远是「添加到通讯录」。一次性成功/失败只用弹层说完。

## 核心判断

1. 产品状态只保留能确定的能力：可添加、未授权写入、接口不支持、号码配置失败。
2. 系统页完成、取消、失败只做一次性反馈，关闭后回到可添加。
3. 主动弹窗仍按 `promptedNumberVersion` 限制次数，不再用“已经保存过”抑制引导或隐藏按钮。

## 支持理由

避免把 API 成功误当成通讯录事实；用户删掉联系人后仍看得到添加入口。

## 反方最强论据

始终显示添加，可能产生重复联系人，也少了一个“我已经处理过”的安心感。

## 失效条件

客服投诉“不知道自己有没有加上”显著上升，且真机来电识别率没有改善。

## Non-goals

- 不申请通讯录读取权限来校验联系人
- 不把埋点里的 `api_success` 映射成页面“已保存”
- 不按已保存/未保存分组统计接通率

## 下一步验证

真机走完添加后，确认小程序界面没有已保存标签，且我的页仍能再次添加。

## 知识沉淀

仅写入权限只能证明“这次打开过系统页”，不能证明“通讯录里现在有这个人”。
