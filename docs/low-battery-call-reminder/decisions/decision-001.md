# 决策卡片 #001

- **日期**：2026-09-09
- **阶段**：MVP

## 决策问题

如何让骑手在电池电量过低时识别并接听智格的固定外呼号码？

## 调用的大师视角

- **俞军 · 用户价值公式**：固定号码只需承担一次保存成本，即可持续降低陌生来电的识别成本。
- **乔布斯 · 极致减法**：先用微信小程序已有能力验证接通率提升，不把跨运营商、跨终端来显能力作为上线前置。
- **Marty Cagan · 探索与交付**：把号码稳定性、保存转化率和接通率提升作为上线前必须验证的风险。

## 核心判断

一期采用方案一：在用户首次领取电池成功后，引导其通过 `wx.addPhoneContact` 把全平台固定外呼号码保存为“智格-电量过低提醒”；取消或拒绝后保留“我的－来电提醒”手动入口。

运营商来显认证不进入本项目范围。

## 支持理由

1. 全平台使用唯一固定号码，联系人匹配具备成立条件；
2. 微信已有通讯录仅写入能力，研发和商务依赖较少；
3. 用户可自主授权、确认和撤销，不影响换电主流程；
4. 可通过保存成功组与未保存组的接通率验证真实价值。

## 反方最强论据

外呼号码由服务商分配，若服务商更换外显号码，已保存联系人会立即失效；同时用户授权、系统确认和重复联系人问题可能使实际成功率低于预期。

## 失效条件

1. 外显号码不固定或存在号码池轮换；
2. 同一号码用于营销、客服等非低电场景；
3. 外呼服务商无法保证呼叫时外显号码等于保存号码；
4. 保存成功组的接通率未产生显著提升。

## Non-goals

- 不读取或搜索用户通讯录；
- 不静默写入联系人；
- 不实现运营商企业来显；
- 不实现短信、订阅消息和真实外呼；
- 不强制用户保存后才能使用换电服务。

## 下一步验证

1. 获取正式外呼号码及服务商稳定性承诺；
2. 用主流 iOS、鸿蒙、Android 真机验证新增、合并、取消和拒绝；
3. 小流量发布后比较保存成功组与未保存组的电话接通率及 30 分钟内换电率；
4. 达不到“接通率相对提升 15%”时停止扩大曝光并复盘原因。

## 知识沉淀

小程序可发起通讯录写入，但用户必须授权并在系统页面确认；产品状态只能表达“本次 API 保存成功”，不能持续证明联系人仍存在。
